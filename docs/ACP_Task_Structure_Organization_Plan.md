# ACP 任务与结构来源命名、标签及检索修改方案

日期：2026-09-18  
状态：已实现（2026-09-18 实施完成；见 §12 实施摘要）  
范围：任务队列重命名；结构来源重命名、多标签整理、搜索、筛选、分组、排序与分页。

## 1. 目标与范围

让用户能够给任务和具体结构设置易读名称，通过标签组织候选结构，并在新建计算任务时找到、辨认和载入所需结构。

本期交付：

1. 所有状态的任务支持重命名及恢复默认名称。
2. 每个可复用结构支持独立重命名及恢复默认名称。
3. 结构支持多标签、批量添加/移除标签和项目内标签管理。
4. 普通任务、BatchOptimize、扫描等结构来源选择入口共享检索与整理能力。
5. 完整来源范围的服务端搜索、筛选、排序、分页，以及来源任务/标签/角色分组。
6. 整理数据持久化、并发冲突保护、审计、旧数据兼容和回归验证。

后续扩展：批量名称替换、自动编号、拖拽排序、收藏、标签自动继承、通用上传结构资产库、修改 TS/INT 计算角色。第一版不提供跨不同方法/体系的能量排序。

## 2. 当前实现与约束

以本次读取的代码为准，历史设计文档仅作背景参考。

| 位置 | 当前行为 | 修改要求 |
|---|---|---|
| `frontend/ACP_Workbench_v2.html::canonicalTaskName` | 优先以目录名作为任务标题 | 增加统一的用户名称展示层，保留目录解析用途 |
| 队列 `buildQueueRow` | 分子分组下优先 task_name + remark | 用户自定义名称应覆盖各分组的默认标题规则 |
| `scheduler/tasks.py` | display_name 属于同步更新字段 | 新增用户维护字段，不能被同步覆盖 |
| `api/v2_routes.py::patch_task` | 可改 molecule_name、task_name、remark、tags | 扩展名称修改与版本检查；保持旧字段行为 |
| `scheduler/structure_sources.py` | 从产物发现来源，ID 为任务 ID + 相对路径 | 保留来源身份，增加独立元数据与可重建索引 |
| `api/v1_routes.py` 来源列表 | recent 接口最多返回 50 项 | 新增完整查询接口，旧接口保持兼容 |
| 前端 `renderResultsList` | 对已取回的最近来源做文本过滤 | 改为服务端完整检索，不局限当前页 |
| 结构 `_parse_structure_meta` | 对外只保留 TS，INT 折叠为空 | 新角色投影保留明确 INT 与未标注的区别 |

必须遵守：任务 ID、计算参数、candidate_id、源 XYZ、manifest、checkpoint、本地/远程 work_dir 不因整理操作而改变；运行中重命名不重启、不暂停计算。现有来源可用性政策保持：已完成任务按工作流发现；失败/取消任务只贡献正式登记的可复用产物。

## 3. 概念及名称规则

| 概念 | 示例 | 权威来源 |
|---|---|---|
| 任务自定义名称 | TS2 路径搜索 | tasks 用户元数据 |
| 结构自定义名称 | TS2 · 成键候选 · 第18帧 | 结构用户元数据 |
| 结构默认名称 | 既有分子/产物名称及候选编号 | 产物发现与默认名称规则 |
| 结构角色 | TS / INT / 未标注 | 原始注释、manifest 元数据及已有推断规则 |
| 分类标签 | 协同路径、待确认、优先计算 | 用户标签关系 |

名称优先级：任务为 custom_name → 现有默认展示规则；结构为 custom_name → 现有来源名称规则。自定义结构名称不再强制附加 candidate_id，编号单独显示在副标题。

“恢复默认名称”清除覆盖值，不修改源名称。界面展示默认名称及真实路径便于追溯；恢复后使用当前默认规则，不承诺恢复某个历史时刻的动态标题。

名称去除首尾空白后须为 1–200 个 Unicode 字符；支持中文和普通标点，拒绝换行、控制字符，按纯文本渲染。前后端统一字符计数。空字符串拒绝；null 表示恢复默认；未传字段表示保持原值。允许同名，以来源任务、时间及 ID 辅助区分。

任务改名只更新结构条目中的来源任务标题，不覆盖结构独立名称，不改变分子分组。结构整理标签不会改动 XYZ 中的 TAG，也不会改变下游计算模式；TS 标记不代表已完成过渡态验证。没有明确 INT 证据的空角色展示为“未标注”。推断角色需带 evidence/source，必要时标为“推断”。本期不重写原有 tag 计算契约。

## 4. 交互设计

### 4.1 任务重命名

- 队列标题旁提供铅笔按钮，悬停或键盘聚焦可见，触屏常显；详情标题提供相同入口。
- 按钮有可访问名称，事件不冒泡到卡片选择、展开或查看操作。
- 使用小弹窗：完整名称输入框、默认名称、简短说明、恢复默认/取消/保存。
- Enter 保存、Esc 取消；名称未变或保存中禁用提交，失败保留输入，成功后恢复焦点。
- 所有任务状态包括排队、运行、暂停、等待确认、终态和归档任务均可编辑。
- 保存成功采用服务端结果更新缓存；不跳转、不改变选择，不强制重置滚动位置。按名称排序时明确允许该项重新定位。

### 4.2 结构来源选择器

```text
选择结构来源
[搜索结构名称、来源任务、候选编号、标签……]
[项目 ▼] [结构角色 ▼] [分类标签 ▼] [更多筛选]
分组：[来源任务 ▼]                  排序：[最新产出 ▼]

▼ TS2 路径搜索                                  8 个结构
□ TS2 · 成键候选 · 第18帧             [重命名] [标签] [载入]
  TS  [协同路径] [待确认]
  编号 pes_ts_018 · 来源 TS2 路径搜索 · 产出时间

已选 2 项（其中 1 项不在当前筛选结果）
[添加标签] [移除标签] [清空选择] [载入所选]
```

- 主标题展示结构名称；副标题展示候选编号、来源任务及产出时间。项目、远程状态、正式/部分结果按需要显示。
- 完整路径、电荷、多重度、分子式等放在详情/预览中；保留现有三维预览能力。
- 结构重命名采用与任务一致的弹窗规则，操作对所有选择器生效。
- 标签编辑支持现有标签搜索、创建和移除；空标签拒绝，去重后每结构最多 20 个、每标签最多 32 字符，复用项目标签的既有规范化规则。
- 项目内提供标签重命名、合并到已有标签、移除标签关系。操作前显示影响结构数量，移除标签不会删除结构。
- 普通任务单选载入；支持多结构的工作流才提供载入所选。整理多选与载入能力分别控制。
- 勾选以稳定 source_uid 保存，跨页保持；更换筛选不偷偷丢弃选择，明确显示隐藏选择数量。
- “全选本页”仅选择本页；第一版不提供隐含的全量跨页选择。批量上限建议 200 项，部分失败逐项反馈，失败项保留选中。
- 一结构在多个标签组中可重复出现，但勾选、计数及载入按身份去重。
- 远程未发现具体产物的任务占位行不当作结构编辑；显示“待同步”及重试入口。

### 4.3 检索与浏览规则

| 能力 | 规则 |
|---|---|
| 搜索 | 自定义/默认名称、原始 label、来源任务当前与原始名称、candidate_id、分子式、标签 |
| 项目 | 默认目标项目；显式切换全部项目或指定来源项目，保持跨项目提示 |
| 筛选 | 角色、分类标签、来源工作流、正式结果/人工候选/部分结果、本地/远程、可用状态 |
| 标签匹配 | 默认任一标签，可切换全部标签；不同筛选维度之间取交集 |
| 分组 | 无、来源任务、分类标签、结构角色；标签分组含未分类 |
| 排序 | 产出时间新→旧/旧→新、名称升/降、最近整理 |
| 时间 | 元数据修改不改变产出时间；最近整理仅使用用户编辑时间 |
| 稳定顺序 | 主排序键相同时用稳定 source_uid 作次排序键；中文/数字自然排序在服务端统一定义 |
| 分页 | 默认 50 项，上限 100；先全范围检索排序、再分页 |

分组查询返回全局组数量和每组分页游标，不把当前一页数量伪装为组总数。标签分组返回独立结构总数与各组成员数，二者不要求相加相等。排序、筛选参数变化使旧游标失效；并发更新可使列表重新加载，但保留选中 ID。

浏览偏好可保存在 localStorage，名称和标签必须持久化到服务端。旧名称仍可通过源名称检索，但第一版不将每次改名历史全部加入搜索。

## 5. 数据与存储设计

### 5.1 任务元数据

向 tasks 增加 nullable custom_name、name_revision（初始 0）、name_updated_at。新字段不加入 _SYNC_COLUMNS，也不在重建任务投影时回填默认覆盖值。

读 API 增加 custom_name、resolved_name、default_name、name_revision。保留现有 display_name 字段的兼容语义；UI 使用 resolved_name，不依赖各处重复拼接。

### 5.2 结构身份、索引和用户元数据

建议分开建立以下表/存储职责，具体表名实施时与现有 migrations 规范对齐：

| 表 | 内容 | 是否可由磁盘重建 |
|---|---|---|
| structure_source_index | source_uid、job_id、规范化相对路径、既有 source_id、project_id、候选编号、默认名、角色证据、来源类别、时间、可用性、发现版本 | 是 |
| structure_source_metadata | source_uid、custom_name、metadata_revision、metadata_updated_at | 否 |
| structure_source_tags | source_uid、规范化标签键、显示文本；唯一关系约束 | 否 |
| organization_events | 对象身份、操作、旧/新值、时间；有身份系统时记录操作者 | 否 |

source_uid 是内部稳定键，首次按规范化 (job_id, relative_path) 唯一身份建立，不能由显示名称生成；保留旧 source_id 读取协议。相对路径须复用路径逃逸校验，不能擅自将大小写折叠，不能用可能跨任务重复的 candidate_id 单独作主键。

发现去重与身份生成共用同一规则。同一产物来自 manifest、兼容清单等多个路径时，先解析真实任务相对路径，再合并。不同实际文件仅在已有权威规则确认是同一产物时合并；不按名称或几何相似度合并。若同一路径内容改变，保留“该产物”的整理信息，更新内容版本/checksum；已经提交的下游快照保持不变。不同路径不自动迁移名称与标签。

索引 upsert 只能更新发现字段，不能覆盖用户元数据。结构标签与现有任务标签分开统计和修改，不自动继承；可共用输入组件。跨项目浏览时按来源项目限定标签管理范围，相同标签文本可用于跨项目筛选，但批量改名标签不能隐式影响其他项目。

### 5.3 生命周期与完整索引

- 初次升级按终态任务分页后台建立来源索引，不能只扫描 recent 的 limit × 3 范围。
- 后续在任务终态、正式候选保存/移除、结果刷新等节点触发增量索引更新，并提供受控重建/刷新入口。
- 远程列表只依赖已缓存的清单与元信息；限并发后台同步，不在每次搜索时遍历 SSH 下载全部 XYZ。
- 返回 indexing_state、pending_jobs、last_indexed_at 等覆盖信息。首次索引未完成时明确提示“仍有来源待索引”，不得声称结果完整。
- 网络失败只标为暂时不可达，不视为产物删除；已知不存在的产物标为不可用，不能载入。
- 源任务 purge 走现有级联清理，清除相应索引、标签和元数据；不影响下游任务已固化的输入快照。不可用来源的详情可以展示元数据，修改操作返回明确状态。
- 用户元数据属于数据库备份范围。重建可派生索引不得删除它；数据库整体丢失时无法仅靠 XYZ 还原自定义名称与标签。

## 6. API 方案

以下为拟新增契约，不表示现有接口已支持。

### 6.1 任务重命名

扩展 `PATCH /api/v2/tasks/{task_id}`：

```json
{"custom_name":"TS2 路径搜索","expected_name_revision":3}
```

恢复默认使用 custom_name:null。只有修改 custom_name 时要求 expected_name_revision，旧客户端修改原有字段保持兼容。使用字段是否显式传入区分省略与 null。更新、版本递增和审计在同一事务内完成；不以会被运行进度更新的 updated_at 作为冲突依据。

返回更新后的名称投影和版本；同值请求在版本有效时为 no-op，不产生无意义审计。404 表示不存在，409 表示版本冲突并携带最新投影，422 表示校验错误。

### 6.2 结构查询与编辑

采用 v2 独立路由，避免被 v1 的 `{source_id:path}` 路由吞掉静态路径：

| 接口 | 用途 |
|---|---|
| GET `/api/v2/structure-sources` | 完整索引查询；q/project/role/tags/tag_match/workflow/source_kind/sort/group_by/cursor/limit |
| GET `/api/v2/structure-sources/facets` | 当前查询下的标签、角色、来源任务计数及独立结构总数 |
| GET `/api/v2/structure-sources/{source_uid}` | 结构元数据详情，携带旧 source_id 供现有坐标载入使用 |
| PATCH `/api/v2/structure-sources/{source_uid}/metadata` | custom_name、分类标签修改及 expected_revision |
| POST `/api/v2/structure-sources/batch-metadata` | 对明确 UID 列表执行 add_tags/remove_tags，每项携带版本 |
| GET `/api/v2/projects/{project_id}/structure-tags` | 项目结构标签及计数 |
| POST `/api/v2/projects/{project_id}/structure-tags/rename` | 项目内改名或合并标签 |
| POST `/api/v2/projects/{project_id}/structure-tags/remove` | 项目内批量移除该标签关系 |

静态路由注册在动态路由前。标签重命名/合并使用项目标签版本进行冲突检查，在事务内处理重复关系并同步受影响结构版本；失败全部回滚。批量结构编辑按单项事务返回成功/失败/冲突清单，重复 UID 去重，不静默跳过错误。

查询返回 resolved_name、custom_name、default_name、role、role_evidence、tags、metadata_revision、job_resolved_name、source_id、source_uid、availability、next_cursor 和索引覆盖信息。服务端负责最终排序；前端不再对一页结果二次排序。

旧 recent 和坐标读取接口保留，通过适配层补充新投影。新增字段须贯穿 Pydantic schema，避免被响应模型丢弃。跨项目操作沿用既有项目访问边界，不能靠前端筛选作权限检查。

## 7. 全界面一致性与下游快照

任务 resolved_name 覆盖队列、详情、当前任务文件面板标题、上下游引用、结果来源、操作提示与任务导出。真实文件树节点仍显示磁盘名称；不要将纯路径用途的 canonicalTaskName 调用机械替换为自定义名。

结构 resolved_name 覆盖所有来源选择器、结构预览、批量输入清单及相应导出。三维查看器通过 source_uid/路径关联时可显示别名，不修改几何、entry_id 或 revision 契约。

任务导出增加自定义/默认名称；结构导出保留自定义/默认名称、标签、角色及证据、来源任务 ID/名称、candidate_id、相对路径。导出范围应明确为所选或当前筛选结果。

载入结构时持有几何和 checksum；提交时固化实际提交的几何以及相匹配的名称/标签/角色元数据版本快照。若预览后修改几何，沿用现有编辑结构溯源规则。后续源结构改名不会追溯改写已经提交任务的输入信息。

续算保留任务自定义名称。重跑建立新任务，可建议“当前显示名称 · 重跑”，但名称只作用于新任务展示字段，不由改名重算原路径。新产出的结构不自动继承原结构自定义名称/标签；输入来源快照保留。

## 9. 迁移、发布与兼容

1. 使用现有数据库 migration 机制增量升级，任务名称默认 null、版本 0；不重写 JobSpec 或物理目录。
2. 先部署可兼容旧 UI 的后端和迁移，再启用新 UI；来源索引在后台分批构建并显示进度。
3. 后端支持字段或能力检测；旧服务不支持编辑时隐藏/禁用入口并解释，不降级为仅本地保存。
4. v1 recent/来源读取、TS tag、结果发现和候选选择行为继续通过原有回归测试。
5. 回退 UI 时保留数据库新字段和表，不破坏整理数据；旧后端是否可运行需用迁移兼容测试确认，不直接假设可逆降级。
6. 本方案交付不包含部署。实际代码发布后按项目服务配置完成重启和烟雾验证。

## 11. 完成定义

任务和结构均可独立重命名；结构可按标签整理并在完整可用范围中检索；各选择入口展示一致；编辑不会改动计算身份、角色或路径；同步、重启和索引重建后整理数据仍保留。代码、迁移、UI、兼容适配与上述验收一起交付，不能以只增加按钮或只支持当前页搜索作为完成。
