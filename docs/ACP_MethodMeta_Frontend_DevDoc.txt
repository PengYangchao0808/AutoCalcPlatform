1. 概述与动机

1.1 目标

将前端中所有泛函相关的硬编码逻辑迁移为API 数据驱动。新增泛函时前端零改动。

v1.5 适用范围勘误: "前端零改动"承诺仅对普通 DFT 泛函（B3LYP/PBE0/wB97X-D4/wB97M-V 等）成立。对复合方法（r2SCAN-3c / PBEh-3c / B97-3c）和波函数方法（DLPNO-CCSD(T)），新增仍需同步修改 src/cccp/qc/interfaces/orca.py 的硬编码分支（详见 R17、R19、R27）。直到 Phase 1 任务 1.6-1.8 完成 ORCA 后端参数化（改为读取 basis_inline + basis_block），此限制持续存在。

1.2 当前问题

 | 位置 | 当前做法 | 问题

   | isFieldAdvanced()
   | 硬编码数组 ["aux_basis","ri_approximation","grid",...]
   | 新增高级字段需改前端

   | 色散框
   | 总是渲染为可选下拉
   | 无法表达"此泛函内置色散不可配置"

   | 默认基组/色散
   | profiles 中硬写每个泛函的默认值
   | 新增泛函需同步改所有 profile

   | RI 加速默认值
   | 硬编码为 "none"
   | 不支持按泛函区分

2. API 响应结构变更

2.1 新增顶层字段

GET /api/v1/method-catalog 返回的 JSON 新增以下字段:

 | 字段 | 类型 | 说明

   | method_meta NEW
   | dict
   | 以泛函名为 key（标准写法，一致于 FIELD_DEFINITIONS 下拉值），值为元数据对象（详见 附录 A）

   | functional_options_map MOD
   | dict
   | 结构不变，但值由 METHOD_META 自动生成（key 使用标准写法，一致于 FIELD_DEFINITIONS 下拉值）

2.2 functional_options_map 与 method_meta 的 key 策略

key 保留标准写法，不做大小写变换。泛函名如 wB97M-V、DLPNO-CCSD(T)、r2SCAN-3c 有其化学文献中的标准写法，不可强制改为全小写。

// key 始终使用标准写法
{ "wB97M-V": {"basis": [...], "dispersion": [...]} }
{ "DLPNO-CCSD(T)": {"basis": [...], "dispersion": [...]} }

查找时使用 case-insensitive 匹配，而非修改 key 本身。前后端分别封装:

 | 层 | 方案

 | 后端 Python | _case_insensitive_get(mapping, key) — 遍历 dict 做 k.lower() == key.lower() 匹配

 | 前端 JS | lookupCI(obj, key) — 遍历对象做 k.toLowerCase() === key.toLowerCase() 匹配

此方案同时满足:
  (1) API 返回的 key 保持标准写法，下游可直接阅读;
  (2) 前端下拉值和用户输入的大小写差异不会导致查找失败。

2.4 method_meta 条目结构

{
  "B3LYP": {
    "basis_inline": true,         // 基组是否拼在 ! 行（true=拼，false=不拼——复合方法或 %basis 块法）
    "supports_ri": true,          // 是否支持 RI 加速
    "default_basis": "def2-TZVPP", // 选择此泛函时默认基组
    "default_dispersion": "D4",    // 选择此泛函时默认色散
    "builtin_dispersion": null,    // 内置色散名称；null=可配置, "D4"=锁定
    "basis": ["def2-SV(P)","def2-SVP",...],   // 允许的基组列表
    "dispersion": ["none","D3","D3BJ","D4"],  // 允许的色散列表
  }

5. 改动 2: getFieldDefault() 泛函级默认值

function getFieldDefault(fieldName, engine) {
    var fd = fieldDefs[fieldName];
    if (!fd) return "";

    if (typeof dflt === "object" && !Array.isArray(dflt)) {
      if (dflt[engine] !== undefined) return dflt[engine];

目标代码

function getFieldDefault(fieldName, engine, functional) {
    // ── 第一优先级: 泛函级默认值 (METHOD_META) ──
    if (functional) {
        var funcMeta = lookupCI(methodCatalogCache.method_meta || {}, functional);
        if (funcMeta) {
            // RI/aux_basis: 泛函不支持则强制返回 无
            if (!funcMeta.supports_ri) {
                if (fieldName === "ri_approximation") return "none";
                if (fieldName === "aux_basis")          return "";
            }
            // default_basis / default_dispersion
            if (fieldName === "basis"       && funcMeta.default_basis       !== undefined) return funcMeta.default_basis;
            if (fieldName === "dispersion"  && funcMeta.default_dispersion  !== undefined) return funcMeta.default_dispersion;
        }
    }

    // ── 第二优先级: 全局默认值 (FIELD_DEFINITIONS) ──
    var fd = (methodCatalogCache.field_definitions || {})[fieldName];
    if (!fd) return "";
    var dflt = fd.default || {};
    if (typeof dflt === "object" && !Array.isArray(dflt)) {
        if (dflt[engine] !== undefined) return dflt[engine];
        if (dflt["*"] !== undefined) return dflt["*"];

    return typeof dflt === "string" || typeof dflt === "number" ? dflt : "";
}

8.1.1 新增: case-insensitive 查找辅助函数

在 <script> 块顶部（全局变量声明区之后，首函数之前）插入:

function lookupCI(obj, key) {
    if (key in obj) return obj[key];          // 快速路径: 精确匹配
    var kl = String(key).toLowerCase();
    for (var k in obj) {
        if (obj.hasOwnProperty(k) && k.toLowerCase() === kl) return obj[k];
    }
    return undefined;
}

本函数在 §§5/6/7 的所有 method_meta 和 functional_options_map 查找中统一使用，替代直接下标访问。无论 API 返回的 key 大小写如何，均能正确匹配。

在 loadMethodCatalog() 成功回调（约 L3802 附近，methodCatalogCache = data; 之后）:

methodCatalogCache = data;
// method_meta 已包含在 methodCatalogCache 中，无需单独提取
// 后续查找统一通过 lookupCI(methodCatalogCache.method_meta || {}, name)

所有 §§5/6/7 示例中 lookupCI(methodCatalogCache.method_meta || {}, ...) 即规范化访问路径。

v1.4 勘误: v1.3 文档称"在 pageInit()（约 L4771）中即发起 loadMethodCatalog()"。实际 无 pageInit 函数，启动逻辑在 window.addEventListener("DOMContentLoaded", async function() {...}) 内（L4752-4806），其中 L4771 通过 safeLoad("loadMethodCatalog", loadMethodCatalog) 触发首次加载。Phase 2 任务 2.5 中提到的"提前到 pageInit()"应理解为"保持在 DOMContentLoaded 启动序列中，并显式处理加载失败"。
