## 1. 目标与边界

**保留当前界面和功能，把 `ACP_Workbench_v2.html` 从混合源码大文件变成可阅读的页面骨架和显式资源入口。** 本轮优化维护结构，不改变页面设计、API、业务规则、科学语义或后端部署要求。

Antigravity 负责从 HTML 中分离现有 CSS、JS、字典和功能代码，修复由拆分引起的依赖/路径/测试问题，并保证每一片在原服务上可运行。OpenCode 同时在独立目录实现 Client、Visualization 和 controller；你按小片交接其模块，在生产入口逐片切换。纯搬运与激活新行为分别提交，不要求等整个 H5 后才开始 AR。

不引入 React/Vue、打包器、TypeScript 编译、Jinja、HTML include 服务、CDN、iframe 或运行时 HTML 片段请求。不复制第二页面、不以 minimal 页面作为回退、不删功能缩减体积，不通过压缩/删除换行制造“行数下降”。

## 4. 与 OpenCode 的写权和顺序

默认方式：**双方同时开发，你独写主页面并逐片接入 OpenCode 已验证模块。** 你不等其全部模块完成即可拆 HTML，OpenCode 不等你拆完即可开发。两者都须对现有后端兼容，不要求同步合入后端改造。

| 范围 | Antigravity 的 H 阶段 | OpenCode 的 AR 阶段 |
|---|---|---|
| 主 HTML、外置样式、原功能分组脚本 | 并行期单写者，拆分及按交接包接入新模块 | 默认只读，提供接口/加载顺序/替换点，不同时改入口 |
| 原 api*/缓存/轮询 | 原样暂存；接入时撤旧 owner/删除或窄委托 | 在 `js/client/**` 实现唯一目标，提供旧符号清理清单 |
| 原 renderer/3Dmol | 已预留符号不另拆第二 feature；负责页面容器接线 | 在 `js/visualization/**` 实现实例/adapter/生命周期 |
| 原全局状态/跨面板流程 | 保留当前含义，登记读写者 | 收敛状态 owner 和 controller |
| DOM/文案/样式 | 保持外观/结构/行为 | 保持现有界面，只接必要内部接口 |
| `tests/test_frontend_sync.py`/既有页面测试 | 并行期单写，适配位置与接线的等效验证 | 可运行，提供新模块专属测试及需接入的断言 |
| 新 controllers/contracts | 默认只读，按纯契约绑定 view 回调 | OpenCode 独写，接口变更先交接 |
| 后端/配置/部署/科学 fixtures | 不默认修改 | 仍归服务/科学负责人 |

H 阶段允许最小装载接线修复，但不顺带更改超时、请求去重、轮询间隔、科学计算或用户操作。若拆一个代码组必须重写状态机/引入新网络行为，该组保留完整过渡块并移交 AR 阶段，不为了目录好看扩大重构。

若 OpenCode 已经开始：先确认双方分支与具体符号归属，选择已合入结果为共同基线；已迁到 Client/Visualization 的代码由 Antigravity 保持原位，不再搬回 compat。可以并行做互不重叠的文件；不能同时搬同一符号、改主 HTML/共享测试或共享可写任务目录。

对已登记由 OpenCode 接管的 api*/renderer/资源刷新，H2 可以先原样外置完整旧脚本以保证当前页面运行，H3 不再将这些符号拆成另一套长期 features。新模块默认不自动 start/联网/挂 viewer，独立验证时不影响旧页面；你在对应接入片中撤旧 owner、删旧实现或改窄委托，再启新模块，不能长期双运行。

不需要替 OpenCode 修新模块内部代码，也不能由它替你改主 HTML。接入遇到问题按 owner 修复；该片不激活时原功能仍由旧实现支持，双方可继续其他独立片。

交接单至少记录原位置/摘要、新文件、符号清单、依赖和执行顺序、共享全局读写、网络/定时器/监听器 owner、已有公开名称、测试迁移及未拆过渡块。OpenCode 以该清单更新引用，不按旧行号继续改。

每片结束页面应可运行，不提交等待后续几片才能修复的默认入口。可独立回退本片完整 HTML/资源组合；不回退 DB、任务目录或科学结果。已发出命令不得因回退或刷新自动重复。

## 6. JavaScript 拆分的关键规则

1. **保持脚本种类与装载顺序。** 本次默认沿用 classic script；不批量添加 async/defer/type=module，不插入异步 loader。保留十个现有业务脚本与主代码的依赖顺序、3Dmol 的异步可选加载和缺库降级。
2. **显式分析顶层执行。** 函数声明、全局 let/const/var、状态初始化、IIFE、事件注册分开登记。不同 script 之间没有整个原大脚本的声明提升；即使源文件顺序不变，早期调用晚期声明也可能失效。循环依赖先保留一个完整组，不能按固定行数或分隔注释机械切割。
3. **不擅自改作用域。** 不给旧脚本整体套 IIFE/namespace，不批量添加 strict，不把共享 let/const 改为 window 属性或复制一份 store；保留内联事件与已有模块可见的公开符号。去全局化交 AR 阶段处理。
4. **不切断闭包或字面量。** 保持 try/finally、模板字符串、字典、函数和 IIFE 完整；拆分依赖符号/语法边界，而不是正则按某个注释位置截取。任何辅助搬运脚本都要核对产物，不让源码带转义损坏。
5. **启动只执行一次。** bootstrap 最后装载仅在依赖已满足时成立；先证明顶层代码未提前读取晚声明对象。保留绑定先于网络请求、目录加载不阻塞任务管理、可选 viewer 不阻塞页面壳等当前行为，不为拆文件重排科学/网络流程。
6. **保留特殊契约。** `api(POST /jobs)` 的编辑重算拦截、写后失效、JSON/文本/FormData、8s/60s 场景超时、调用方取消和 SSE/原刷新保持原行为；energy viewer 只保存候选，framing 与模式编号/帧身份不变。

不通过执行时 `eval`、Function、document.write 或获取文本后拼接执行来恢复原大脚本的作用域；这会把维护问题变成装载机制问题。确需新的初始化接口时列成最小变更并验证调用次数/顺序，而不是顺带重做架构。

## 7. CSS、DOM 与资源规则

- H1 新 link 位于原 style 的位置，仍先于已有 structure/source/task-input 等外部样式；不把它随意移到最后覆盖原规则。
- H4 保持规则的覆盖优先级、完整 @media/@supports/keyframes、CSS 变量作用域和媒体断点。重复 selector 可以表达有意覆盖，不在搬运时合并/排序/去重；重新分组改变 cascade 时须证明等价，否则按原连续段保留顺序。
- CSS 中 `url(...)` 外置后解析基址会变化，逐个核对图片/字体等相对路径；只修路径，不引入远程资源。脚本若依赖 currentScript/源路径等机制同样核对，不凭搜索未发现就断言不存在动态依赖。
- 保留静态 DOM 的 ID/data-*、顺序、容器尺寸、隐藏状态和选择器关系；不整体替换 innerHTML 造成监听器丢失或 viewer 重建。沿用原 resize/可见性与 framing 入口。
- 十五个 active 工作流、历史/retired 兼容分支和所有现有菜单/弹窗均保留；不能因名称“legacy”或页面当前隐藏就删除。
- HTML/link/script 引用只走现有静态根，默认首页和 `/legacy/` 路由保持。旧偏好/布局/草稿可读，不能通过清 localStorage 修拆分回归。

## 8. 测试迁移与验收

现有 `tests/test_frontend_sync.py` 大量读取主 HTML 并定位函数/CSS/字典；其语法检查也只抽取内联 script。把代码搬出后，断言失败不一定是行为回归，但不能简单删断言或把注释留在 HTML 骗检查。

测试按真实责任迁移：

| 原检查 | 迁移后检查 |
|---|---|
| HTML 中的函数/常量/字典断言 | 定位实际新源文件；字典键/默认值仍与原契约一致 |
| HTML 中的 CSS selector/rule 断言 | 定位实际样式文件，并验证 HTML 中 link 的加载顺序 |
| 只检查一个内联 script 语法 | 检查全部一方 JS 与剩余内联脚本；跨文件依赖仍需真实浏览器 |
| 动态行为/Node harness | 以约定依赖顺序加载；不只把所有文件拼回一个字符串来隐藏跨 script 提升差异 |
| 禁止提交/唯一入口等护栏 | 扩大覆盖迁移后的所有对应文件，确保没有漏扫 |
| 默认页与静态资源 | 用 S0 真实 HTTP 检查状态、内容类型、引用、完整性和初始化 |

可增加一个只供测试使用的资源清单/读取 helper，避免每个断言重复路径；它不得成为新的服务接口或运行时构建前置。区分 markup、JS、CSS；不要让测试中的“HTML”继续代表随意拼接全部源码的虚拟页面。

优先复用 `test_frontend_sync`、startup、interaction、structure_picker、candidate_workspace、viewer_framing、multiframe_playback、measure_edit 等现有测试。修改断言前登记原断言→新断言映射及等效/更强证据；测试文件本身的全面重构不与 HTML 搬运混成一个大变更。

必需验收：

1. F1＋S0：后端源码/配置/依赖/DB schema 不改，首页/新增静态资源无加载错误，无新的 ReferenceError/重复注册/脚本顺序故障。
2. 同数据同窗口：三栏布局、折叠/拖动、结构/能量/路径/已有其他视图、任务列表/详情、向导与弹窗保持；中文/英文、窄面板、隐藏后展开及现有断点无回归。检查 DOM/关键计算样式和截图，动态时间/WebGL 渲染不强求逐像素完全一致。
3. 原操作：列表/分页/选择、上传/预览、方法配置、候选、编辑重算、任务控制/恢复、历史结果和适用远端读取。写操作使用隔离任务；重点确认编辑重算没有额外创建任务。
4. 原刷新/资源行为：请求和定时器没有因拆分翻倍，跨标签/任务切换不残留动画或监听器；科学 ID/单位/原生模式序号、导出与 framing 保持。
5. 首屏不新增运行时 HTML 片段请求或全量科学载荷；脚本/CSS 请求数可以因拆分增加，记录量测，不虚报速度提升。3Dmol/catalog 延迟或失败时原页面壳仍可用。
6. 冷加载、普通刷新、暖缓存、旧标签页和整套资源回退可用；保留支持窗口内旧静态资源，先备资源再切引用，不只回退 HTML。

结果分别记录 PASS/FAIL/NOT_VERIFIED；真实 API/浏览器缺失时不能宣称独立运行已验证。真实科学软件/LSF 按适用环境单列，不为原样外置 CSS 而重跑全部科学算法。

完成证据包括主 HTML/各文件的行数分布、符号与依赖地图、搬运与必要逻辑变更清单、测试映射/结果、页面对照与真实 S0 验证、未拆代码组原因、OpenCode 接手位置及回退清单。行数减少本身不等于维护性或性能验收通过。
