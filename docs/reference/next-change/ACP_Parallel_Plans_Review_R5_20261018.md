**剩余一处：M1 的安装验收仍间接等待完整发行**

[C-T54](.omo/plans/acp-parallel-plan-3-cccp.md:793) 的前置仍无条件包含 T40；[T40](.omo/plans/acp-parallel-plan-3-cccp.md:637) 等待 T39；[T39](.omo/plans/acp-parallel-plan-3-cccp.md:626) 等待 T30/T33/T38，其中 T30 收口 NMR 迁移、T33 是大数据交付。

```text
M1 发布 → 必须通过 T54 → T40 → T39 → T30 / T33 / T38
```

因此，T54 正文虽然写明“未选 NMR 等能力不阻塞 M1”，执行依赖仍会等待它们。C-T51 和最终验收又使用“全部 todo”，尚未与本次 release 的声明范围统一。这影响首批发布排期，不阻断正在进行的基线、契约和迁移开发。

建议只调整相关子项与范围规则：

- **T40a：本次范围的安装预验**，消费本批构建规格、已完成的所选科学闭包与依赖清单；不无条件等待完整 T39。
- **T40b：完整发行安装预验**，保留 T39 及完整 NMR/大数据等前置与验收要求。
- **T54：本次候选发布前复验**，等待对应范围的 T40a 或 T40b、B 应用回执以及候选源码/构建输入冻结；不改变发布前必须验证实际候选产物的要求。
- **T51/F1–F4**：里程碑验收检查本次 `IN_SCOPE` 任务及其必要依赖、T54；全路线最终关闭才检查全部任务。未选能力保留 DEFERRED，必需上游不能用 DEFERRED 绕过。

可用“仅选择一个已独立 simple 工作流、NMR 和大数据未选”的调度场景核对：应能到达候选安装验收与发布前终验，同时 T30/T33 保持未完成且不被错误宣称交付。
