## 3. 需要收口的 3 处

### 3.1 C-T54 必须是发布前的合并版本验收

**位置：** [C-T54](<repo>/.omo/plans/acp-parallel-plan-3-cccp.md:788)、[C 最终验收规则](<repo>/.omo/plans/acp-parallel-plan-3-cccp.md:821)、Success criteria 的 IS-10。

T54 本身仍是“B 应用打包补丁后，对合并提交重建、安装并运行科学样例”，任务头明确 `Blocks: B release`。但新的 F-wave 注释与 IS-10 又把它归为“发布后结果核对”，并从发布前终验排除。两处语义相反。

**应修改为：**

- B 的“应用回执”指补丁已进入集成候选提交，**不代表已部署生产**。
- 候选源码和打包配置冻结后，C 执行 T54；通过后才允许 B 的发布前终验及实际发布。
- 删除 C F-wave 中“T54 为发布结果核对”的例外；IS-10 恢复为发布前证据。
- C-T51 最终索引在 T54 后汇总本次范围证据；生产部署和部署冒烟归 B-T76/F5。
- 若发布的是 M1 子集，T54 验证该子集的实际安装产物；完整 NMR 模型/报告的运行要求只对已声明支持的范围生效。资产完整性仍按实际随包清单检查。

正确顺序：

```mermaid
flowchart LR
    A[B 应用到集成候选] --> C[候选源码与构建配置冻结]
    C --> V[C-T54 合并版本安装复验]
    V --> F[发布前终验]
    F --> R[B-T76 实际发布]
    R --> P[B-F5 发布结果核对]
```

这项修订必须在发布冻结前完成；不妨碍前序开发。B 侧已经修好的发布前/后划分应保留。

### 3.2 B-T32 的真实入口切换必须等待 T77/T78

**位置：** [B-T32](<repo>/.omo/plans/acp-parallel-plan-2-services.md:491)、[B-T77](<repo>/.omo/plans/acp-parallel-plan-2-services.md:459)、[B-T78](<repo>/.omo/plans/acp-parallel-plan-2-services.md:521)。

T77/T78 已补齐迁移和 worker 装配，但 T32 仍只等待 T30–T31 和 C01。按任务头计算，T32 的数字前置闭包只有 `{1,2,3,30,31,72}`，不含 T77/T78；因此执行入口可以在旧实现尚未移除、独立装配尚未通过时切换。T32 自身的独立入口测试也会提前消费尚未完成的产物。

**应修改为：**

- T31 负责协议和可测试的执行核心，可提前开发。
- T77 迁移声明范围内的实际依赖；T78 实现并验证新进程自足装配。
- T32 的真实切换子项显式等待 **T78 + 对应工作流 C-T10a/闭包交付**；T78 已传递依赖 T77/T31，不必重复维护所有边。
- T33/T34a、相应 CLI 闭环沿这条链取得前置；准备脚本或转换器的纯开发可提前，但不能提前启用。

顺序为 `T31 → T77 → T78 → T32 → T33/T34a`，不存在新增的反向依赖。

另将 T77 的“无 jobs DB 连接”限定为 **worker 独立性探针**。迁移后的 controller/store 的持久化、CAS、恢复验收应连接隔离测试数据库；整个 Services 并非禁止数据库连接。这样可以保留 worker 边界，又不使存储层验收自相矛盾。

### 3.3 在 B 计划中实际接收 C 的科学产品 adapter

**位置：** [C-T13](<repo>/.omo/plans/acp-parallel-plan-3-cccp.md:335)、[B-T28](<repo>/.omo/plans/acp-parallel-plan-2-services.md:439)、A-GT3。

C-T13 已要求写出 B 侧任务号或 B-T28 子项；A-GT3 也等待 B 的 frames/annotation adapter。但当前 B-T28 仍只实施已有发布入口、markers 和 manifest 的收敛，没有新增产品→frames/annotation 的 adapter 范围、前置和验收。仅让交付方在未来登记任务号，不等于接收方已有实现任务。

**建议直接拆 B-T28：**

| 子项 | 内容 | 前置与退出 |
| --- | --- | --- |
| B28a | 既有 Data 发布/markers 入口收敛 | 保留当前前置和契约时序，不等待整套新科学产品 |
| B28b | 本次支持的科学产品→frames/annotation adapter、旧结果 reader/转换、发布与读取接线 | 等 C-T13 契约/fixture 及对应生产入口；经 `to_node()/to_annotation()` 输出；由 A-GT3/B-T75 消费验收 |

每种产品按本次范围独立验收，覆盖单位、原子/帧/模式/点身份、partial/unavailable、旧版本与损坏输入。同一 fixture 应贯穿 C 生产、B 发布/投影、A 消费；不会因为某个未选产品未完成就阻塞既有任务发布。

这项应在 GT3 激活前完成任务定义，adapter 实装在对应产品交付后进行。
