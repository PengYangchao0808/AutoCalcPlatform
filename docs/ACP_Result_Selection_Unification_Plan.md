# ACP 选点展示与任务结果统一修改方案

日期：2026-09-30  
状态：已于 2026-10-01 落地业务代码与回归；实施范围、测试结果及现场验收边界见 [实施与验收记录](ACP_Result_Selection_Unification_Implementation.md)。  
依据：用户四条需求、截图、附件现状梳理，以及当前工作区源码。附件用于理解现状，其中的历史规则不作为新需求。工作区已有重算界面相关未提交修改，本方案将其纳入基线并保留。

## 1. 建议采用的总规则

**按“结构生成步骤是否成功”决定结果保留，按“目标任务需要什么”决定展示顺序，按“当前编辑的是哪个对象”决定右侧操作。**

五件事独立记录：

1. 计算产生了什么几何、该步骤是否收敛。
2. 哪些几何可作为可复用结果自动登记。
3. 用户手动保存了哪些帧，以及赋予了什么角色。
4. 哪些结构正在被查看、哪些已加入本次输入。
5. 下游任务是否满足提交条件。

“可复用”不表示已验证为正确 TS/INT；“被查看”不表示已选为输入；“整个任务失败”不表示此前成功结构无效。

本方案中“不保留选点”指**不自动加入可复用结构库**。日志、轨迹、频率、能量、检查点仍保留在任务结果中供诊断与人工选帧。FREQ/SP/NMR 的科学结果仍正常展示和下载。

### 2.2 验证范围

本轮运行了临时隔离验证，没有修改业务源码：

- 调用实际来源筛选函数：两个 irc_endpoint 被排除，structure 类型的 IRC path 被选中。
- 调用实际 reconcileSelection：选择 A、B 后，旧索引 0 仍指向 A；事件回调没有更新焦点对象。
- 对实际 candidate_details 模块使用最小 DOM 替身和延迟响应：草稿为新名称时，晚到响应重新渲染旧名称；重复 setEntry 会重置编辑状态。
- 对实际通用 executor 写入函数使用内存 manifest 替身：failed OPT 的附件仍被分类为 structure。此验证确认发布条件缺失，不等于所有失败任务都会被最终来源库展示。

这些验证确认了代码缺陷，**尚未在截图对应的在线服务完成浏览器操作复现**。因此不把全部现场症状归因于单一原因；上线验收必须覆盖真实鼠标、键盘、网络延迟及远程任务。

## 3. 第一条：完整的结果保留规则

### 3.1 工作流矩阵

| 工作流或阶段 | 自动进入可复用结果 | 不自动进入的内容 | 展示与补充规则 |
|---|---|---|---|
| 普通 OPT / xTB OPT | 有明确收敛证据的最终单帧 | 未收敛最后一步、崩溃残留、仅 SCF 收敛的几何 | OPT 失败时自动结果为 0；轨迹允许人工保存 |
| OptTS / tsmode 的优化阶段 | 成功收敛的优化几何 | 失败的优化末帧 | 保留“TS 目标/候选”角色；频率和模式验证独立展示 |
| OPT→FREQ→SP→热化学 | OPT 成功后立即持久化其输出 | FREQ/SP 对同一坐标的重复副本 | 后续任意阶段失败、取消、超时，仍保留该 OPT 结果，标出中断阶段 |
| 多次 OPT 的串联流程 | 每个独立成功 OPT 阶段的版本 | 失败的后续 OPT 末帧 | 默认显示最近成功版本，前序成功版本折叠；后一步失败不撤销前一步 |
| BatchOptimize | 每个 item 独立应用上述规则 | 失败 item 的未收敛几何 | 保留成功项及 OPT 成功的部分完成项，不能按整个批任务状态一刀切 |
| 纯 FREQ / SP / 热化学 | 不新增结构来源 | 输入几何的拷贝 | 结果页显示属性报告和“所用结构”来源链接；可从原来源发起下一任务 |
| 纯 NMR 屏蔽/分析/DP4/DP5 | 不新增结构来源 | GIAO/分析输出中的同坐标副本 | 保留光谱、位移、概率等结果与几何引用 |
| 含构象搜索或 OPT 的 NMR 综合流程 | 前置结构生成阶段的成功产物，按对应阶段规则登记 | NMR 阶段本身的重复几何 | 不按 nmr 工作流名称整体禁用所有结构；明确产物来自哪个前置阶段 |
| IRC，双方向成功 | forward、reverse 各一个独立端点 | 整条路径、多帧 XYZ 被当成单帧 | 两端并列、固定方向顺序；不根据 forward/reverse 自动推断反应物/产物 |
| IRC，仅一方向成功 | 有终点证据的成功方向端点 | 另一方向中断的末帧 | 显示“端点 1/2，另一方向未完成”；中断末帧可人工保存 |
| IRC，明确只请求一方向 | 所请求方向的成功端点 | 未请求方向的虚构输出 | 显示“端点 1/1”及方向 |
| PESsearch | 用户明确保存的人工选点 | 算法推荐、自动 TS/INT 种子、未确认峰值 | PES2TS 完成并独立验收之前，关闭自动推荐计算与展示；完整曲线和所有可读帧仍可查看 |
| 普通 scan | 用户保存的帧 | 自动把扫描终点当无约束优化结果 | 每帧携带约束信息；与 PES 一致采用手动选点展示 |
| Confsearch | 已发布构象集合内的有效、去重后单构象 | 原始 MD 帧、失败优化帧、整份 ensemble XYZ 作为单结构 | 建议保留全部正式入选构象，默认展开 rank-1，其余折叠；显示相同能量口径下的排序与筛选范围 |
| 手工结构/上传/编辑另存 | 用户明确保存的结构版本 | 单纯预览、尚未解析的输入 | 来源为人工，验证状态为未验证；未执行计算不能自动宣称收敛 |
| 退役工作流历史结果 | 兼容读取已登记产物或有确切成功证据的产物 | 从文件名猜测成功后自动升级 | 保持历史可读；缺证据显示“历史状态未知”，不伪造 TS 验证 |

Confsearch 的“全部正式入选构象”是本方案新增建议，替代当前仅 rank-1 的发现限制。它不扩大为全部采样帧。rank-1 可以在任务详情默认展开，但不默认勾选为新任务输入。

### 3.2 保留条件

自动登记优化结果须同时满足：

- 该次优化步骤存在明确的几何收敛证据，并绑定本次 attempt、item、stage。
- 坐标完整、数值有限、元素与原子顺序有效；单帧结构产品不能由多帧文件的第一帧冒充。
- 已写入稳定产物位置并记录内容校验值，不能只存易被后续阶段覆盖的工作文件路径。

不以“文件存在”“退出码为零”“整个任务 COMPLETED”替代几何收敛证据。未知状态不自动提升为成功。验证失败与优化失败分开：例如 OPT 收敛而 TS 频率判断失败，仍保留几何，但显式显示“TS 验证未通过”。

手动保存失败轨迹帧允许继续保留，记录 `selection_origin=manual`、源帧和未收敛状态；用户改成 TS 标签不能把收敛状态改成成功。手工输入仍可用于后续优化。

IRC 的端点身份、方向完成状态、连接性验证、端点是否另做 OPT/FREQ 分别记录。端点坐标可复用不等于已验证为稳定极小值。双方向坐标相同也保留两条方向来源，显示“几何相同”，不能去重掉一个端点。

### 3.3 发布时机与中断处理

1. 每个结构生成步骤成功后，立即原子写入结构、阶段记录、manifest；之后再启动 FREQ/SP。
2. 后续失败只更新执行状态和验证状态，不移除已发布结构。
3. 库的默认发现继续面向终态任务，避免扩大当前运行中输入规则；运行中任务详情可只读展示“已完成阶段结构”。
4. 进程中断后，恢复逻辑只根据已持久化的成功阶段记录补登记，不能扫描到一个 XYZ 就认作成功。
5. 失败的更高精度 OPT 之前若已有低精度 OPT 成功，保留低精度版本并显示计算层级；不冒称最终目标层级已完成。
6. 跳过或从检查点恢复的阶段，只有输入指纹和方法指纹匹配才复用旧成功证据。

## 4. 统一结果与来源的数据规则

### 4.1 建立一个共享判定模块

建议新增 `src/acp/results/structure_policy.py`，供 manifest 发布、来源发现、重算输出投影、v1/v2 API 与提交预览共同使用。计算引擎提供事实，该模块给出是否自动登记及原因，避免每个界面自行猜测。

最少输出字段如下；优先扩展既有 manifest metadata 和来源投影，避免同时维护另一份竞争性权威清单。

| 字段组 | 建议内容 |
|---|---|
| 身份 | source_uid、version_id、product_id、job_id、attempt、item_id、stage_id；已有 UID 保持兼容 |
| 几何 | content checksum、元素/原子数、charge、multiplicity、单帧/集合类型、几何引用 |
| 来源 | optimization / irc_endpoint / conformer / manual_frame / manual_asset；父结构、帧号、IRC direction |
| 计算事实 | geometry_changed、optimization_status、stage_status、workflow_status、方法层级、收敛证据位置 |
| 角色 | role=TS/INT/未指定；role_origin、角色修订号；不复用自定义标签表达角色 |
| 验证 | frequency_status、stationary_point_status、TS 模式/IRC 连接性结果、警告 |
| 策略 | auto_reusable、reason_code、policy_version、selected_by_user |
| 可用性 | available / pending_fetch / pending_sync / missing / invalid；从验证与可用性推导提交资格 |

`source_kind=partial_result` 不再只由整个任务 FAILED 推导。部分完成是执行维度，optimization 是结构来源维度，二者必须能同时表达。

当前几何版本机制在拿不到校验值时会使用 unknown 占位；新方案需要补充真实内容校验值，不能把占位 hash 当作几何相同的证据。

### 4.2 产品类型与去重

- `structure` 表示可解析的单结构；`irc_endpoint` 作为受支持的单结构专用类型读取。
- 轨迹继续是 trajectory/明确 collection，保留查看入口，不能直接加入单结构输入。
- 兼容历史误登记 IRC path：根据已知产品语义与帧数识别为集合，提供“打开轨迹并选帧”。
- 同一源结构经过纯 SP/FREQ/NMR，只增加属性和使用记录，不创建新结构身份。
- 几何相同但来自不同任务、方法或 IRC 方向，折叠展示关联关系，不删除来源证据。
- 身份优先使用 source_uid + version_id；hash 仅做几何相似/相同提示，不凭 hash 合并来源。

### 4.3 更新和重建索引

- `refresh_job` 使用事务内的发现字段 upsert 和失效标记，保留 metadata、tags、assessment、usage_status。
- 删除整个任务才走真正的 cascade purge。索引刷新不得调用 `delete_by_job`。
- 发现暂时为空要区分“成功扫描后确实无结果”和“远程读取失败”；后者不撤销已有来源。
- manifest 变更、手动保存/撤销、任务终态、远程目录同步完成都触发同一增量刷新。
- 无结构的已处理任务也记录索引状态，不能永远被统计为待同步。
- 新规则带 discovery/policy 版本，后台重建支持重复执行、分批恢复，不改用户的名称、标签与回收站状态。

## 5. 第二条：初始化窗口的 TAG 分类与排序

### 5.1 将标签拆成四个展示维度

| 维度 | 示例 | 修改权限 |
|---|---|---|
| 结构角色 | TS 候选、INT/极小值目标、未指定 | 用户可设置；同时保留来源角色和本次输入覆盖值 |
| 结构出处 | 优化结果、IRC 正向端点、IRC 反向端点、构象、人工选帧 | 程序根据来源生成 |
| 计算/验证状态 | OPT 已收敛、FREQ 失败、TS 待验证、人工保存未收敛帧 | 程序根据证据生成，不能通过改标签篡改 |
| 用户标签 | stepwise、concerted、publication、待重算 | 用户管理 |

“TS”不使用成功绿色来暗示已经验证。颜色与文字区分角色和状态；空角色显示“未指定”，不再只显示 `--`。

已有 `role_evidence` 延续使用，角色读取顺序统一为明确用户版本→结构化产品元数据→XYZ TAG→历史兼容推断。推断结果标明“历史推断”，不从名字中自动确证化学身份。

### 5.2 按目标任务提供快捷分类

| 目标任务 | 默认优先展示 | 次级展示/条件 |
|---|---|---|
| 普通 OPT / xTB OPT | INT、IRC 端点、构象、普通人工结构 | TS 候选仍可见；改走普通 OPT 前展示角色用途差异 |
| BatchOptimize，包含 TS 计算 | TS 候选分组优先；组内已收敛可重算结构、人工 TS 初猜 | INT 组并列可选，每项角色决定所走优化分支 |
| BatchOptimize，仅极小值优化 | INT、IRC 端点、构象 | 未指定角色需明确本次优化用途，避免静默套用 INT |
| IRC | 满足现有 IRC 准入规则的 TS 来源 | TS 候选但验证/文件不足的条目可查看，并显示缺失项；不降低现有校验 |
| tsmode | 有可用 Hessian/模式信息且满足现有来源契约的条目 | 仅带 TS TAG 的几何不足以通过；保留版本映射 launch gate |
| FREQ | 已收敛、尚未做频率或频率失败的几何 | 其他单结构仍可选择，显示收敛信息 |
| SP | 有效优化结构、正式构象、已保存扫描帧 | 坐标不变的任务不要求增加新的几何产物 |
| NMR | INT/构象集合中的适用单结构 | 保留现有电荷、多重度、候选与实验输入规则 |
| Confsearch | 普通结构、INT、可编辑上传结构 | 旧构象可重新搜索；不强行要求频率已验证 |
| PESsearch / scan | 满足源输入契约的优化结构/构象 | 展示来源与约束；不提供 TS/INT 算法推荐 |

这些是**展示优先级**，服务端提交资格仍由工作流能力和输入契约校验，不能只靠 TAG 放行。标成 INT/TS 的工作流用途不应反过来修改源结构的已验证化学结论。

向导如果先选结构后选任务，在第一步顶部显示“目标任务：未选择”，使用通用分类；选定或修改任务后更新排序、显示不兼容原因，保留已选集合。重算已知工作流，打开时直接采用对应分类。规则来自活动 catalog，新增工作流必须登记展示策略；不写死退役默认值。

### 5.3 页面分组与默认排序

页面保留“全部 / 人工候选 / 任务产物”，上方增加角色、结果类型、验证状态、来源任务快捷筛选与数量。

默认显示顺序：

1. 本次输入，以及重算时的上次输出固定区域。
2. 符合当前任务用途的结构。
3. 与当前任务直接关联的源结构、同一分子组结构。
4. 同组按相应验证状态、产生时间倒序；相同时间用稳定 ID 排序。

组内保留自然顺序：Batch 按 item 次序；IRC forward→reverse；构象按同一能量口径下的 rank。不同方法的能量不能混为一个全局“最低能量”排序。用户手动选的排序覆盖默认智能排序，但不取消顶部输入/输出定位区。

排序、分类计数、分页必须由服务端在分页前统一计算。`context_workflow`、角色优先级、排序版本等纳入 cursor 指纹，不能只对当前页重新排序。跨页勾选按稳定身份保存。

### 5.4 推荐的行信息

每行主信息为“结构名称｜角色｜结果类型｜来源任务｜计算状态｜操作”。次行可显示 item/候选编号、方法、时间与用户标签。较少使用的信息进入详情。

例：`TS2 优化结构｜TS 候选｜OPT 结果｜TS2_STEPWISE｜OPT ✓ · FREQ ✗`。

整条路径显示为“IRC 反向轨迹 · N 帧 · 打开选帧”，不能使用普通结构复选框。回收站不参与正常输入选择。未加载几何但来源有效的条目可加入待加载列表；加载完成前不能提交，失败提供重试。

## 6. 第三条：名称编辑 BUG 与修复

### 6.1 截图涉及三种不同名称

- 来源任务名称：由任务重命名 API 更新，影响来源列和任务列表。
- 结构库名称：更新结构来源 metadata.custom_name，影响该来源的长期显示。
- 本次输入名称：仅覆盖本次任务输入，可与库名称不同。

截图右侧的“名称”绑定 `wif-name`，当前编辑的是第三种，不能把它当成来源任务名称。真正的库重命名入口藏在“标签与评估”的折叠详情里；行菜单没有显式重命名入口。应明确这三个编辑范围。

### 6.2 精确故障链

**A. 勾选和编辑焦点未同步。**

checkbox change→合并 wizardStructures→按旧 wizardSelectedStructureIndex 刷新表单。选 B 并不会让 B 成为编辑对象。输入表单 change 回调又从全局索引取对象，用户很难确认修改落到谁上。

**B. 预览态会禁用“名称”，但页面没有足够明确的操作入口。**

行 click→previewStructureSource。若结构不在本次输入中，则 `_refreshWizardInputForm(struct, true)` 禁用四个字段。反复点击和双击都不会将其变成输入。用户可能在查看 B 的同时，输入列表中的活动项仍为 A。

**C. 异步详情重绘打断编辑。**

setEntry 先渲染再异步 refresh。用户立即点击编辑并输入后，晚到响应无条件 `_render()`；输入从旧 `_entry.custom_name` 生成，host.innerHTML 替换整个表单。隔离验证中，新值还留在 dirtyFields，但界面已显示旧值，形成“显示值与将保存值不一致”。同一行再次 setEntry 也没有身份相同的短路。

**D. 几何请求缺少统一焦点约束。**

previewStructureSource 使用一个预览 token，但勾选回调、输入列表切换和 `_loadPendingGeometry` 不共享同一对象焦点版本。它们可以独立回填右侧表单，造成先后响应覆盖。此项需补真实乱序网络验收。

### 6.3 修复后的交互约定

1. 行单击：聚焦该来源，立即同步高亮、名称、来源和右侧加载态；随后加载几何。无需双击。
2. 复选框：只改变是否加入本次输入；新加入单项时同步聚焦该项。批量全选保持原焦点。
3. 未加入输入：右侧可编辑“结构库名称”；“本次输入设置”显示加入按钮和清晰说明。
4. 已加入输入：右侧显示独立的“本次输入设置”，编辑本次名称/角色/电荷/多重度。
5. 行 `⋯` 增加“重命名结构”“重命名来源任务”“本次输入设置”。任务重命名必须使用 job→task 的已解析映射，不能误传结构 ID。
6. 单击“重命名结构”直接聚焦名称框；Enter 保存、Escape 取消。F2 可作为快捷键，不能成为唯一入口。
7. 编辑同一对象期间再次点击同一行不清空草稿。切换对象有未保存修改时才显示明确的保存/放弃选择。

### 6.4 状态模型和实现落点

将输入工作区的状态归并到 `task_input_workspace.js`，逐步收回 HTML 中重复的状态逻辑：

- `focusedSourceKey`：当前正在看的来源及版本。
- `selectedInputs`：本次提交集合，以 input_id 为身份。
- `editingTarget`：明确 scope=task/source/input 和对应稳定 ID。
- `draftByTarget`：该对象的表单值和 dirty 字段。
- `focusGeneration`：窗口、焦点或版本改变时递增，所有异步回填共同验证。

移除以数组位置作为编辑身份的做法；删除、排序、分页后按 input_id/source_uid 重新定位。响应只更新匹配对象的数据缓存，只有仍匹配焦点时才更新右侧。

`candidate_details.refresh` 不得覆盖 dirty 字段；允许更新未编辑的状态信息。必须重绘时由 draft 渲染、恢复焦点与光标，不再从旧服务器值重建。keydown 等宿主监听只安装一次。

保存后以服务端返回的 revision 和名称为准，同步 picker、详情、来源缓存及尚未做本次名称覆盖的输入。已存在本次覆盖值时保留它。409 冲突展示当前服务器值和用户草稿，不静默丢弃或覆盖。

## 7. 第四条：重算的输入与输出高亮

### 7.1 同时展示三类身份

| 身份 | 视觉 | 语义 |
|---|---|---|
| 本次输入 | 蓝色边框/徽章 + 勾选图标 | 来自当前 selectedInputs，用户改变输入时实时更新 |
| 上次输出 | 紫色边框/徽章 + 输出图标 | 上一 attempt 的全部可复用输出，是稳定历史快照 |
| 上次输入 | 灰色徽章“上次输入/默认起点” | 帮助溯源，不冒充当前输入 |
| 正在查看 | 独立的细轮廓/焦点指示 | 只表示预览对象 |

同一结构既是本次输入又是上次输出时，**同时显示蓝、紫两个徽章**，不能用 if/else 丢掉一个身份。颜色必须配文字和图标，不依赖色觉。

### 7.2 顶部固定定位区

结构库列表顶部显示两组紧凑卡片：`本次输入（N）`、`上次可复用输出（M）`。列表中的对应行也带同色标记。

- 固定区独立解析 ID，不能依赖当前分页是否恰好包含该来源。
- 受筛选隐藏时仍在固定区可查看，标注“当前筛选外”，提供定位到来源。
- Batch 输出按 item 对齐，支持逐项或全部替换输入；替换先显示配对预览，不能按数组顺序配错。
- IRC 两端都列出；选择哪一端是显式操作。
- 打开重算默认保留原输入，上次输出只供查看/替换，不自动多加进输入集合。
- 替换输出改变输入并不表示跳过原工作流的 OPT；只有专门支持的继续/阶段重试才改变执行计划。
- 无输出显示原因：OPT 未收敛、纯属性任务、PES 未手动选点、未请求该方向、历史证据不足等。远程同步中显示加载态，不能误报“没有结果”。

### 7.3 后端契约

将单个 `last_structure` 扩展为 `previous_outputs[]`，返回 item、stage、attempt、direction、来源 UID/版本、几何可用性、收敛与验证摘要。

过渡期可保留 last_structure 兼容字段，但新界面只消费数组。单项选择仅作为兼容投影，不能成为新系统的权威。

`edit-draft` 与结果来源发现共用策略和远程读取根解析；小型目录由后台预取，几何按需获取，必要时由 draft 定向获取要展示/使用的输出。沿用 RemoteStructureCache 单例、超时与重试机制。

来源身份比较使用 UID+版本、产品身份或明确 job/attempt/path 关系。当前“source_id、hash、checksum 任一相等就匹配”的方式需收紧：几何相同不代表是同一次输出；在相同路径上重算也不代表是同一版本。

### 7.4 原地重算前必须保存旧结果

当前 manager 原地重算会清理 WORK/RESULT，数据库 attempt_history 并不保存结构内容。这与“保留成功 OPT 供以后再用”存在生命周期冲突。

建议在 run_root 下建立独立、按内容校验值寻址的结构快照存储，只保存可复用几何及小型来源记录；物理路径不使用 job_id/时间戳。来源记录关联 job、attempt、item、stage 和旧 product。

重算顺序：解析并校验输入→持久化输入快照及上次可复用输出→写引用/操作记录→按现有 strict 规则清理→入队。快照失败就停止本次重算并保留旧目录。远程任务也必须先确认快照可读取，不能只依赖会过期的远程缓存。

历史来源版本绑定快照，新 attempt 更新当前版本；不要把旧名称、评估自动应用到内容不同的新版本。已有 UID 兼容保持，通过版本和 attempt 区分。快照清理按引用计数和明确保留规则执行，不随着缓存 TTL 消失。

## 8. PES 暂停自动推荐的完整范围

设置显式产品能力 `selection_mode=manual_only`。新 PESsearch 执行不调用推荐器，也不生成自动选中的 TS/INT ID；保留路径分析、能量、约束残差、收敛信息和轨迹。

必须同时处理以下出口：

- `pes/scan.py` 的推荐计算入口及返回字段。
- `pes/engine.py` 的 ts/int candidates、selected_ts_id/selected_int_id、推荐审计产物。
- `results/energy_graph.py` 的自动推荐标记与候选合并。
- `/s2/profile`、`/s2/candidates`、结果清单、导出内容的推荐投影。
- 工作台曲线、候选卡片、加载推荐按钮，以及当前未提交的重算路径帧卡片。
- CLI/from-job 的下游加载仍要求明确人工确认，不能因旧 recommendations 文件存在而恢复自动入口。

兼容 API 可返回空推荐数组并解释 manual_only；历史推荐文件只保留在审计区，不继续投影成当前推荐。已经人工确认的历史点保留，不能误删。

人工选点链路保持：查看曲线→选择确切帧→指定本次 TS/INT 用途→明确保存→结构库可见→统一创建任务。保留终态失败/取消任务从可读部分帧保存的能力；运行中/暂停任务先查看，终态后保存，沿用现有一致性边界。

保存前校验完整 XYZ、有限坐标、原子数与元素顺序、帧身份、源版本、目录边界；报告未收敛/约束偏差，允许用户明确保存作初猜。没有频率的候选不伪装成已验证 TS。

PES 整体替换确认集合与普通帧候选增删接口可以继续内部共存，但 UI 明确显示保存模式；不可让用户以为新增一个点会保留旧集合，实际却把旧点删掉。保存完成反馈新增/保留/移除数量和版本冲突。

## 9. 界面整合

### 9.1 任务结果页

顶部显示任务执行结果及独立的结构摘要，例如：`任务失败：FREQ 错误；保留 1 个已收敛 OPT 结构`。

保留四个明确区域：

1. **可复用结构**：优化结果、IRC 两端、正式构象，显示阶段状态。
2. **人工选点**：保存的帧，含来源轨迹和人工角色。
3. **曲线与轨迹**：全部可读帧；失败末帧保留用于诊断和手动保存。
4. **属性报告与文件**：频率、能量、NMR、热化学、日志及完整下载。

任务结果页、创建窗口、重算窗口消费相同来源投影，名称、数量、角色、可用状态必须一致。能量查看器继续只保存候选，任务提交统一进入创建流程。

### 9.2 小型状态说明

每个结果显示“为何保留/为何未保留”的短理由，详情可展开证据。不要让用户从文件树猜测。

- `OPT 已收敛；SP 失败，此结构可用于重算。`
- `OPT 未收敛，未自动生成结果结构。可打开轨迹手动选帧。`
- `此任务仅计算频率，使用的结构见来源。`
- `IRC 正向端点已保存；反向计算未完成。`
- `PES 当前采用人工选点，已保存 2 个候选。`

## 11. 历史数据、远程和迁移

1. 先部署能读新旧类型的 reader，再部署新 writer，最后分批重建索引。
2. 修正 IRC path/endpoint 的发现类型；不删除历史轨迹文件，不依赖改名。
3. 对失败的 OPT→后续阶段任务，从检查点、阶段记录和对应计算输出补证据。有明确成功证据才补登记；没有则保留为诊断/手动入口。
4. 历史重建只改发现字段，保留自定义名称、标签、角色修订、人工评估、回收站状态。
5. 旧纯属性结构如果已经被引用，保留可解析别名/历史引用，在新建来源中隐藏重复项，不直接使旧任务输入失效。
6. 远程发现必须使用统一读取根和 RemoteStructureCache；小目录自动预取，几何按需下载。手动保存使用现有先结构后权威记录的写回流程。
7. 区分目录未同步、几何待下载、确实不存在、校验不通过；任何网络失败都不能当成“结构数量为 0”的确定结果。
8. 明确源版本变化：已加入输入保持快照，提示源有新版本；提交前检查使用/回收站状态与版本，不静默替换。
9. 项目移动、任务改名、结构改名不改变几何身份或物理任务路径；显示名称和路径职责分开。
10. 新策略关闭后仍须能读取已生成快照与结构；回滚 UI 不得删除新格式数据。

## 13. 最终应达到的用户体验

用户看到失败任务时，能立即知道“哪些结构已经成功、哪些后续步骤失败”；打开创建或重算窗口时，能按任务用途找到结构，清楚辨认本次输入与上次输出；单击目标即可编辑正确对象，保存后的名称与标签经刷新仍在。

完成标准是这四条在本地、远程、批量、部分失败和历史任务上都成立。
