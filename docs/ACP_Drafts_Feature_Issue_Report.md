# 草稿箱功能问题报告

**检查日期：** 2026-09-27  
**检查范围：** Workbench v2 新建任务草稿箱、草稿 API、快照保存与恢复、现有自动化测试  
**结论：** 草稿箱已有持久化 CRUD 和基础恢复流程，但当前功能不能视为完整可用。截图中的列表加载 404 是入口级阻断；当前源码包含对应 API，因此需结合实际运行服务确认部署/路由状态。另有一项源码可确认的工作流状态丢失问题。

## 问题清单

### P1 — 草稿读写接口在截图对应运行实例返回 404（已修复并验证）

第一张截图显示草稿列表 `GET /api/v1/drafts` 返回“Not Found”；补充截图中，关闭窗口触发自动保存时也弹出“草稿保存失败：Not Found”，对应首次保存的 `POST /api/v1/drafts`。前端 API helper 会把服务端 `detail` 原样作为错误消息显示。当前工作区中，`drafts.py` 定义了这两个接口，API server 也新增了 `/api/v1` 路由注册。

源码检查发现，草稿箱前端改动目前是工作区未提交内容，`src/acp/api/drafts.py` 是未跟踪文件，`server.py` 中草稿路由导入和注册也是未提交改动。运行实例当时的 OpenAPI 路由表确实没有草稿接口，因此根因是后端进程尚未加载新增路由。已确认 systemd 服务从当前工作区启动，且当时运行/暂停任务均为 0；重启 ACP 服务后，`GET /api/v1/drafts` 返回成功，OpenAPI 已列出列表和单条草稿路由。

**影响：** 用户无法查看、恢复、保存或删除草稿；窗口关闭时保存失败且窗口保持打开，草稿箱主要流程均受阻。

**证据：** [Workbench v2 前端 API 地址与草稿列表加载](../frontend/ACP_Workbench_v2.html)；[草稿 API 路由](../src/acp/api/drafts.py)；[API server 路由注册](../src/acp/api/server.py)。

### P1 — 机制研究草稿恢复时丢失专属状态（已在当前工作区修复）

`_captureWizardDraft()` 保存了结构列表、通用表单字段、`wizardState` 和 PES 选点状态，但没有保存机制研究的 `reactionDefinition` 与 `mechCoordinatePlans`。策略、保真度、构象模式、步数/扫描点等部分选项虽作为控件值进入通用字段快照，`openModal()` 仍会把对应全局状态重置为默认值；`_restoreWizardDraft()` 只回填 DOM 值、不触发变更处理器，也不恢复这些全局状态。提交组装逻辑读取这些全局变量，因此界面上恢复出的控件值可能与实际提交配置不一致。

因此，用户编辑机制研究任务后关闭并恢复草稿，反应物/产物/TS 猜测、人工键变化、反应坐标计划及相关策略设置会回到空值或默认值。虽然部分输入字段会从通用字段快照恢复，但这些全局机制模型状态不会恢复。

**影响：** 机制研究任务存在静默丢失配置的风险，用户可能基于不完整配置继续提交。

**证据：** [Workbench v2 草稿快照与恢复实现](../frontend/ACP_Workbench_v2.html)；机制状态定义和重置逻辑也位于该文件的 `reactionDefinition` / `mechCoordinatePlans` 状态块及 `openModal()` 初始化段。

### P2 — 草稿箱测试未覆盖前端恢复和关键工作流状态（仍待补充）

现有 `test_acp_drafts.py` 覆盖 API 创建、列表、读取、更新、revision 冲突和删除，但测试是将草稿 router 单独挂到临时 FastAPI 实例，没有覆盖生产 `server.py` 的路由注册。`test_frontend_sync.py` 对草稿相关功能主要检查控件/文案存在。当前测试没有验证完整前端行为，例如从列表恢复后字段及结构是否正确、机制研究状态是否保留、从一个草稿切换到另一个草稿、空白任务的字段重置、提交后清理，以及实际服务路由可达性。

**影响：** 已知的机制状态恢复缺口没有被测试发现；入口路径与运行版本不一致时，现有测试也不能代表部署实例可用。

**证据：** [草稿 API 测试](../tests/test_acp_drafts.py)；[前端契约测试](../tests/test_frontend_sync.py)。

## 当前已实现部分

- 后端提供草稿创建、列表、读取、更新和删除接口，并将快照存入 SQLite。
- 更新使用 revision 乐观并发检查；快照大小限制为 8 MiB。
- 前端具备 1.5 秒防抖自动保存、关闭前保存、恢复、删除、新建空白和提交后清理逻辑。
- 通用快照包含表单控件值、结构条目、向导步骤、工作流状态，以及 PES 选点信息；文件对象不持久化，未解析的上传文件恢复时会提示重新上传。

## 建议修复顺序

1. 重启/重新部署 ACP 服务后，确认截图对应实例的 `/api/v1/drafts` 读写路由可达。
2. 后续补充前端恢复契约覆盖，包括一般工作流往返、机制研究状态往返、草稿切换和提交清理。

## 结论边界

本报告包含源码检查、用户提供的截图，以及重启后对运行实例的只读 API 检查；未运行自动化测试。当前工作区已修复机制状态往返与草稿保存时序，草稿 API 的运行时 404 已通过重启服务解决。

## 后续改进记录（2026-09-27）

- 已扩展快照契约，保存/恢复机制研究反应定义、手工坐标计划、策略参数和 study ID；恢复会重新渲染面板并同步提交使用的全局状态。
- 结构解析和来源结构加载完成后会重新安排自动保存，避免异步操作晚于防抖快照而遗漏新结构。
- 恢复草稿前会先保存当前打开的编辑器，包括恢复同一份草稿的情况；过期的创建请求可清理新建记录，过期的更新请求不会删除原草稿。
- 删除当前正在编辑的草稿时会先取消待执行防抖保存并等待在途保存完成，再删除记录，降低删除后被旧请求干扰的风险。
- 404、草稿不存在和 revision 冲突会显示可操作的提示；草稿列表查询只读取摘要列，避免加载每个快照正文。
- ACP systemd 服务已重启；`GET /api/v1/drafts` 返回成功，OpenAPI 路由表包含 `/api/v1/drafts` 和 `/api/v1/drafts/{draft_id}`。草稿列表当前有 0 条记录；服务状态正常，运行/暂停任务均为 0。
