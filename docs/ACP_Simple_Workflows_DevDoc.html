5.5 Stage 间数据传递链（optfreqsp 关键设计）

optfreqsp 的管线涉及三个 stage，每个 stage 的输出需要作为下一 stage 的输入。数据流如下：

 ingest (结构文件)
   │
   │  coordinates, symbols, charge, multiplicity
   ▼
 opt_freq (ORCA Opt Freq)
   │
   │  ├─ coordinates （优化后坐标）→ 传给 single_point
   │  ├─ energy （优化能量）
   │  ├─ frequencies （频率列表）
   │  └─ log_file （ORCA .out 路径）→ 传给 shermo
   ▼
 single_point (ORCA SP, 使用 opt_freq 输出的坐标)
   │
   │  ├─ energy （高精度单点能）
   │  └─ log_file
   ▼
  shermo (读取 opt_freq 的 log_file 计算热化学修正)
    │
    │  ├─ zpe, enthalpy, gibbs_correction, entropy
    │  └─ gibbs_correction → 传给 finalize（不含 SP energy）
    ▼
  finalize (SP energy + gibbs_correction → 最终自由能 → thermo.json)

实现要点：

  • simple.py 内部维护一个 context: dict[str, Any] 在 stage 间传递中间数据，包括 opt_coords, opt_log_path, sp_energy 等。
  • Shermo 阶段调用实际位于 conformer_search.qc.runners.run_shermo()，通过 acp.backends.external 重导出（external.py:3，__all__ 包含 run_shermo）。调用路径：from acp.backends.external import run_shermo。传入 opt_freq 的 log 文件路径。Shermo 只输出热化学修正值（gibbs_correction, zpe, enthalpy, entropy），不含单点能。
  • finalize 阶段手动计算最终自由能：free_energy = sp_energy + shermo_gibbs_correction（Shermo 默认以输入 log 的电子能量为参考，而 opt_freq 的电子能量精度低于 SP 级别，因此必须替换为 SP energy）。
    • ⚠️ 单位转换（Critical）： Shermo 默认输出热化学修正值单位为 kcal/mol，而 ORCA SP energy 单位为 Hartree。finalize 阶段必须调用 acp.core.models.HARTREE_TO_KCAL（或 conformer_search.utils.constants.HARTREE_TO_KCAL）将 SP energy 转换为 kcal/mol 后求和，或在自由能输出时统一为 Hartree。两个模块均定义了该常量（v4.0 审查确认），但注意两处值一致（627.509 kcal/mol）。建议 finalize 使用 from acp.core.models import HARTREE_TO_KCAL。
  • method_levels_to_workflow_config() 对非 confsearch schema 直接返回 dict(levels)，simple.py 收到后将三层 levels 分别路由到对应的 backend 调用（orca → opt_freq, orca → single_point, shermo → thermochemistry）。
  • --nproc / --maxcore 从 CLI 参数传入后，通过 **kwargs 透传到 ORCABackend → ORCAInterface。ORCAInterface 已有 _build_input_blocks() 将其写入 %maxcore 和 %pal nprocs 块（通过 pal_settings 和 maxcore 参数）。simple.py 的 handler 需显式提取 nproc 和 maxcore 并作为 kwargs 传入 ORCA backend：
    orca_kwargs = {}
if nproc:
    orca_kwargs["pal_settings"] = f"nprocs {nproc}"
if maxcore:
    orca_kwargs["maxcore"] = maxcore
result = backend.opt_freq(coords, symbols, charge=charge, multiplicity=mult, output_dir=out_dir, **orca_kwargs)

5.6 错误处理策略

各 stage 的错误处理遵循以下规则：

场景行为说明
输入文件格式不支持抛出 ValueError（含支持的格式列表）在 handler 最外层捕获，统一通过 CLI/scheduler 报告给用户
ORCA 子进程非零退出读取 ORCA .out 文件末尾错误信息，封装为 RuntimeError 抛出不吞异常；scheduler 将 job 标记为 failed 并保留 .out 文件供排查
ORCA 输出频率解析失败记录 warning log（frequencies 字段设为空列表，has_frequencies=False），继续执行非致命错误：thermo/Shermo 阶段会因缺少频率而跳过
Shermo 二进制未找到optfreqsp 的 shermo stage 抛出 FileNotFoundError，终止管线在 simple.py handler 中调用 shutil.which("shermo") 前置检查
optfreqsp 某中间 stage 失败整个 job 失败，不执行后续 stage由 scheduler 的 job lifecycle 管理（manager.py），StagePlan 的 depends_on 字段确保顺序依赖
输出目录冲突自动追加 _1, _2... 唯一化调用 _ensure_unique_dir()，无覆盖风险
Shermo 输出解析失败抛出 ValueError，热化学字段留空thermo.json 中 zpe/enthalpy/gibbs_correction/entropy 设为 0.0，success: false 标记

def _ensure_unique_dir(base_dir: str | Path) -> Path:
    base = Path(base_dir).resolve()
    if not base.exists():
        base.mkdir(parents=True)
        return base
    counter = 1
    while True:
        candidate = base.parent / f"{base.name}_{counter}"
        if not candidate.exists():
            candidate.mkdir(parents=True)
            return candidate
        counter += 1

method_levels_to_cli_flags() 具体实现

在 catalog.py 中新增以下函数，供 _build_cmd() 及其它需要将 level 映射为 CLI 参数的模块调用：

_LEVEL_TO_CLI_FLAG_MAP: dict[str, str] = {
    "functional": "method",
    "basis": "basis",
    "aux_basis": "sp-aux-basis",
    "ri_approximation": "sp-ri-approximation",
    "dispersion": "dispersion",
    "solvent_model": "solvent-model",
    "solvent": "solvent",
    "temperature": "temperature",
    "pressure": "pressure",
    "scale_factor": "scale-factor",
    "max_steps": "geom-maxiter",
    "opt_convergence": "opt-convergence",
    "grid": "grid",
    "scf_convergence": "scf-convergence",
}

def method_levels_to_cli_flags(
    levels: dict[str, Any],
    prefix_map: dict[str, str] | None = None,
) -> list[str]:
    """Convert method levels dict to CLI flag list.

    Args:
        levels: Nested dict - e.g. {"optfreq": {...}, "single_point": {...}}.
        prefix_map: level_id → CLI flag prefix (default: no prefix for all).

    Returns:
        CLI flag list - e.g. ["--method", "wB97M-V", "--basis", "def2-TZVPP"].
    """
    prefix_map = prefix_map or {}
    cmd: list[str] = []
    for level_id, level_config in levels.items():
        prefix = prefix_map.get(level_id, "")
        for field, value in level_config.items():
            if field == "engine" or value is None or value == "":
                continue
            cli_flag = _LEVEL_TO_CLI_FLAG_MAP.get(field)
            if cli_flag is None:
                continue
            flag = f"--{prefix}{cli_flag}"
            cmd += [flag, str(value)]
    return cmd

用法示例（_build_cmd 中）：

from acp.catalog import method_levels_to_cli_flags

# optfreqsp 的 prefix_map：optfreq 无前缀，single_point 使用 --sp- 前缀
prefix_map = {"optfreq": "", "single_point": "sp-", "thermo": ""}
cmd += method_levels_to_cli_flags(levels, prefix_map)
