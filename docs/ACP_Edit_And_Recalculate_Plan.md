# ACP 全任务「修改参数后重算」实施计划

日期：2026-09-19  
状态：**已实现（P1–P4 全部交付，2026-09-19）**。落地清单：`src/acp/scheduler/job_edit.py`（草稿/覆盖注册/差异/指纹/幂等操作记录）、迁移 018 `job_edit_operations`、`manager.edit_recalculate()`（与 rerun 共享 `_inplace_requeue_locked` 公共链 + 严格清理）、API 三接口（GET `/api/v1/jobs/{id}/edit-draft`、POST `.../edit-recalculate/preview`、POST `.../edit-recalculate`）、`frontend/js/job_editor.js`（ACPJobEditor 编辑链）+ Workbench v2 ↻ 三项菜单/编辑横幅/api 拦截。测试：`tests/test_acp_job_edit.py`（56 项，11 工作流往返/幂等/冲突/清理阻断）+ `tests/test_frontend_sync.py` 编辑链契约 + 浏览器 E2E 25/25。  
适用入口：任务队列、任务详情。  
设计原则：复用现有任务创建页面、结构来源选择器、参数卡片、预览及提交校验，补齐从已有任务到可编辑草稿的回填链路。

## 1. 目标与实施边界

用户从任意有效任务点击「修改参数后重算」，进入原任务对应的现有编辑页面，看到完整原配置，修改后选择原地重算或创建新任务。打开和取消编辑不改变任务，不启动计算，不清理结果。

本期必须覆盖当前全部有效工作流，不以只完成 BatchOptimize 作为交付：singlepoint、optimize、frequency、scan、irc、casscf、xtb_optimize、nmr、Confsearch、PESsearch、BatchOptimize。任务目录的新增工作流须显式注册编辑适配能力，缺少适配时测试失败，不能悄悄缺失入口。

历史退役任务全部覆盖「识别、查看旧参数、解释兼容性、可行时迁移为新任务」；不通过本功能重新开放已退休的执行入口。custom_sequence 当前为 planned，不新增其执行能力。

前端串联是主要工作。不另建通用工作流引擎、不重做创建向导、不增加独立草稿数据库、不建立第二套参数默认值。后端只补齐回填投影、参数校验、修改后重算提交及必要的一致性保护。

## 2. 已确认的代码基础

| 现有能力 | 位置/行为 | 复用方法 |
|---|---|---|

注意：当前 rerun 已不是旧说明中的「创建新任务」。它会清理 WORK/RESULT、旧日志和标记，保留稳定身份/输入文件；历史尝试仅保留摘要。因此编辑重算要明确清理含义，并在清理前准备好全部新输入依赖。

## 3. 操作定义

| 操作 | 参数 | 输入 | 身份与产物 |
|---|---|---|---|
| 直接重跑 | 沿用原配置 | 原输入 | 按现有原地重跑规则执行 |
| 修改参数后重算 | 回填后可编辑 | 默认原输入，可显式替换 | 默认原地重算，也可切换创建新任务 |
| 复制为新任务 | 回填后可编辑 | 默认原输入，可替换 | 新 ID、新目录，保留原结果 |
| 续算 | 受检查点兼容规则约束 | 现有检查点 | 保持原有续算功能，不由本功能代替 |

「从最后有效结构开始」是一次新的计算尝试，不表示恢复检查点。GBW/Hessian/其他重启文件仅通过已有显式参数复用并校验；不得自动继承旧 WORK 目录中的文件。

## 4. 队列与表单交互

### 4.1 入口

队列中现有 ↻ 按钮打开轻量菜单，包含「直接重跑」「修改参数后重算」「复制为新任务」。详情页提供相同操作。名称旁铅笔仍只表示重命名。

菜单由服务端能力投影决定可执行动作及禁用原因，不由前端散落的状态判断单独决定。触屏、键盘都可打开，点击菜单不触发卡片选择/展开。首次打开显示加载状态，失败时显示具体原因，不能展示未回填的空表单冒充旧参数。

### 4.2 编辑模式

```text
修改参数后重算
来源：TS2_Concerted_BatchOptimize · 已取消 · 第 1 次尝试

[任务信息] [输入结构] [计算参数] [计算资源]

输入：● 原始输入  ○ 最后有效结构  ○ 选择帧/结果  ○ 替换输入
执行：● 原地重算  ○ 创建新任务

已修改 3 项                              [查看差异]
[取消]                                  [检查并提交]
```

- 共用已有页面字段，不复制一套 HTML 表单。
- 默认使用原始输入和原工作流；不读取当前查看器选中帧作为隐式输入。
- 原地重算锁定工作流、来源项目、物理目录；名称只按已有显示名称机制修改。
- 创建新任务允许改项目与工作流；更换工作流仅迁移明确兼容的输入/参数，展示未迁移项目并重新校验。
- 页面显示参数回填完整性、缺失输入及旧默认值差异；必要字段缺失时允许补齐后提交。
- 取消不写数据库。关闭有改动的表单时提供留在页面/放弃草稿选项。
- 保存中禁用重复点击；请求失败保留草稿与错误。打开另一任务使用新加载 token，旧响应不得覆盖当前表单。
- 创建模式与编辑模式反复切换必须完全重置状态，防止 TS 参数、约束、NMR 文件等泄漏到下一任务。

### 4.3 最终提交摘要

显示工作流、输入结构来源/周期/收敛状态、项目、执行目标，以及实际修改项的原值和新值。资源改变与科学参数改变分别列出，继承值变化也显示实际影响。

原地按钮：「应用修改并原地重算」。摘要明确「将清理旧 WORK/RESULT 和日志；保存参数与输入的尝试摘要，不保存完整旧结果」。不增加重复确认弹窗，最后一步摘要即提交确认。

新任务按钮：「创建新任务并计算」。默认建议名为「原显示名称 · 修改重算」，目录继续使用现有命名去重规则，不把 ID/时间戳加入路径。提交成功刷新队列、选中新任务或原任务，显示排队状态。

## 5. 全工作流覆盖矩阵

下表参数是必须核对的范围，实际字段名以当前 catalog、schema、序列化和执行器为准，不能从表中另造不受支持的参数。

| 有效任务 | 必须完整回填 | 输入及特殊校验 |
|---|---|---|
| singlepoint | 后端、方法/基组、溶剂、SCF、高级输入、资源 | 单结构、电荷/多重度；保持原子顺序 |
| optimize | 单点公共项、优化收敛/步数/约束、已有救援设置 | 可选择最后有效几何；替换后重新校验约束原子编号 |
| frequency | 方法、频率类型及已有热化学配置、资源 | 未优化结构可显式选择，不能伪装为已收敛；复用 Hessian 必须满足已有兼容检查 |
| scan | 坐标类型、原子编号、起止/步数/方向、约束、方法 | 多坐标顺序及单位保持；替换结构后编号不得静默重映射 |
| irc | TS 输入、正反方向、步长/点数、方法、现有 Hessian 配置 | 提示输入角色与 Hessian 可用性；不能把普通最后帧自动视为 TS |
| casscf | 当前支持的活性空间、电子/轨道数、态及权重、方法和辅助文件 | 按实际 schema 验证电子/自旋及轨道输入；复用已有动态参数卡片，缺控件时仅补控件 |
| xtb_optimize | xTB 方法级别、溶剂、收敛、约束、资源 | 保留 charge/multiplicity 到 xTB 参数的现有映射 |
| Confsearch | 四种协议、资源 profile、采样/筛选/精修、温度/能窗等已有配置 | 初始结构与原解析快照；不同协议分支不互相残留字段 |
| PESsearch | 来源 manifest/候选、路径/扫描配置、原子映射、候选策略、已有方法层级 | 需要 manifest 时完整保留依赖，不能仅回填一个 XYZ；保持手选与自动配置差别 |
| BatchOptimize | profile、公共参数、TS/INT 覆盖、单项覆盖、SP/频率/热化学、并行度 | 完整逐项输入清单、角色、候选 ID、电荷/多重度、约束；保留列表顺序 |
| nmr | 构象来源/搜索、屏蔽计算、溶剂、平均/等价/指认、DP4/DP5、已有枚举选项 | 实验数据、候选结构和模型依赖均须回填；附件路径失效时要求替换 |

Confsearch 协议覆盖 xtb-crest、xtb-md、censo-crest、xtbmd-censo。BatchOptimize 覆盖 opt_only、opt_freq、opt_freq_sp、opt_freq_sp_thermo，以及 INT/TS 混合清单。

所有有效任务均支持在原输入基础上修改参数重算。额外的「最后有效结构」仅在该工作流确实提供可验证几何时启用；没有结构时禁用该选项，不影响原输入重算。

### 5.1 历史与 planned 工作流

| 历史类型 | 编辑与迁移策略 |
|---|---|
| optfreq、optfreqsp | 可建议对应 BatchOptimize profile；经逐字段和输入验证后创建新任务 |
| Lowconfirm、Highconfirm | 可建议 BatchOptimize；不能仅凭名称选择 profile，保留原 TS/INT 与多层配置并展示差异 |
| ensemble、energy、xtbmd_censo_energy、conformer、mech-conf | 展示原配置；根据原协议与输入验证 Confsearch 等目标的可迁移范围，不能预设完全等价 |
| mechanism、mech-step、mech-confirm、mech-chain | 展示旧计划及产物，用户选择可复用结构/manifest，迁移到现有 PESsearch/BatchOptimize/irc 等单任务入口；不自动声称完整链等价 |
| benchmark | 展示参数，允许提取兼容输入创建有效任务，不重新启用旧基准执行器 |
| custom_sequence（planned） | 明确尚未支持执行；可查看历史配置，不提供虚假的原地重算按钮 |

历史任务原地编辑重算禁用；迁移仅创建新任务。只有实际验证通过的迁移才可提交，未支持映射的字段显式列出。

## 6. 参数恢复与输入规则

### 6.1 参数恢复

1. 服务端数据库 JobSpec 为原始提交参数权威，job.json 用于核对/受控兼容回退，不由浏览器拼路径读取。
2. 原任务有效配置用于恢复当时默认值并展示实际行为，不把 BatchOptimize 的有效配置文件强套给其他工作流。
3. 结构优先使用实际物化的输入快照和来源信息，不能仅用 SMILES 重新嵌入代替原坐标。
4. 解析参数保持省略/null/false/0/空列表的不同含义。路径引用、角色覆盖、单位、数组顺序不能在回填中丢失。
5. 先恢复公共值和继承关系，再恢复工作流特定值、角色及单项覆盖，最后生成有效预览。不要把有效配置简单扁平化成所有字段的显式覆盖。
6. 历史默认不明确的字段标为未恢复；可使用当前默认但必须显示差异并由用户检查，不能标为原值。
7. 表单不认识但后端仍支持的参数放入「保留的高级参数」只读摘要，提交时由受控字段白名单合并；不支持/退役参数需移除或迁移后才能提交。
8. 无修改往返应满足 normalize(原配置) == normalize(回填再提交配置)，比较计算语义，排除时间、进度、任务 ID 等运行字段。

### 6.2 输入依赖

- 输入是一个依赖集合：XYZ、多结构清单、manifest、实验文件、约束以及被明确选用的计算辅助文件，不能只复制 input.xyz。
- 选择最后帧时展示文件/周期/产生时间及几何校验结果；先形成独立快照，再进入旧目录清理。
- 远程输入先通过现有安全获取接口完成拉取和校验；不可达时保留草稿，不能用空输入继续。
- 替换结构后校验原子数、元素顺序、原子编号引用及角色；不确定的映射要求重新选择坐标/约束。
- 批量任务默认重算完整清单；允许显式勾选部分结构，摘要显示原数量与新数量，不自动只取失败项。
- 新输入写入后更新 input_source、输入 hash、TaskIndex 相关输入投影；不得让稳定保留的旧 input.xyz 覆盖新选择。
- 新建任务必须复制所需输入，不能只保存即将被清理的源 WORK/RESULT 路径。

## 7. 状态与可执行性

| 原状态 | 打开草稿 | 原地重算 | 创建新任务 |
|---|---|---|---|
| completed / failed / cancelled | 是 | 校验通过后允许 | 是 |
| queued / starting / pending / running | 是 | 禁用；明确先取消并等待终态 | 输入依赖已固化时允许 |
| paused / cancelling / waiting_review | 是 | 禁用；按现有操作先达到终态 | 输入依赖可用时允许 |
| archived | 是 | 终态有效任务可用；成功后取消归档并明确提示 | 是 |
| 主表缺失的幽灵条目 | 否，展示失效说明 | 否 | 仅存在独立有效输入时通过普通新建入口操作 |
| retired / planned | 兼容查看 | 否 | 按迁移能力或有效工作流新建 |

不在编辑提交中隐式取消运行任务；避免把取消与破坏性重跑组合成难以恢复的动作。状态允许性必须在实际提交时再次校验。

## 8. 最小前端改造

新增轻量 editorContext：mode、sourceJobId、sourceAttempt、sourceRevision、originalDraft、workingDraft、inputRefs、executionMode、requestToken。

将现有 openModal 的大量初始化拆成可复用步骤，而不是回填后再次调用会清空参数的函数：

```text
openJobEditor(context)
  → resetEditorState()
  → 等待 catalog / 项目 / 节点等选项
  → workflowAdapter.mountExistingForm()
  → workflowAdapter.hydrate(draft)
  → 恢复输入预览、依赖字段及最终配置预览
  → 开放编辑

submitEditor()
  → workflowAdapter.serialize()
  → 现有前端校验
  → 服务端检查与差异摘要
  → edit_recalculate 提交或现有创建提交内部链
```

hydrate 阶段设置 restoring 标记，避免 change 监听器重置子字段；回填完成后只做一次派生 UI 更新。异步默认值响应必须受 token/模式保护。

适配器只有 hydrate/serialize/validate 的必要差异：简单任务共用一份；Confsearch、PESsearch/scan、BatchOptimize、nmr、casscf 补特定字段。优先复用已有参数 schema 和收集函数，不每个工作流复制完整表单。

可新增 frontend/js/job_editor.js 管理上下文和适配注册，Workbench 只保留入口绑定。中英文文案同步。采用项目实际托管页面及前端同步规则，不盲目复制整份 v2 到 v1。

## 9. 后端接口与并发约定

以下为拟议接口，保持旧 rerun、continue、clone 调用兼容。

| 接口 | 作用 |
|---|---|
| GET `/api/v1/jobs/{id}/edit-draft` | 返回标准草稿、输入描述、能力、缺失项、来源配置/尝试指纹 |
| POST `/api/v1/jobs/{id}/edit-recalculate/preview` | 复用当前校验/有效配置解析，返回规范化草稿、差异、警告、阻断原因和提交指纹 |
| POST `/api/v1/jobs/{id}/edit-recalculate` | 校验后原地重算或一次性创建新任务 |

草稿响应至少包含 workflow、editable_spec、input_refs、source_revision、attempt、capabilities、preserved_fields、missing_fields。输入描述引用已授权的服务端来源，提交时重验路径与归属，不能接受任意服务器路径作为编辑指令。

提交体包含 mode（in_place/new_job）、editable_spec、input_refs、expected_source_revision、preview_fingerprint、request_id。客户端不能写入状态/PID/remote_job_id/work_dir/result 等运行字段。

- source_revision 根据原计算配置、尝试编号及输入版本生成；常规进度更新不会制造伪冲突。状态资格独立复查。
- preview_fingerprint 绑定服务端规范化后的配置/输入版本；提交再次校验，不能仅信任浏览器的差异摘要。
- 同 request_id、同负载重复提交返回同一结果；同 ID 不同负载返回冲突。持久化最小操作记录/唯一约束，覆盖网络重试与服务重启，不能只依赖按钮禁用。
- 返回实际 job_id、attempt、operation 状态；409 表示配置/状态/输入版本冲突，422 表示参数错误，404 表示来源失效，输入暂不可达返回可重试错误。
- 全部预览/提交共用创建流程的参数解析器，避免新建可用而重算不合法，或相反。

## 10. 原地重算执行顺序

复用 rerun 内部流程，抽取支持 validated_spec/prepared_inputs 的公共执行方法；禁止先调用旧 rerun 排队后再修改 spec。

1. 完成配置校验、工作流能力校验、输入解析与依赖准备，产生可提交快照。
2. 获取每任务执行互斥；重新读取记录，检查终态、source_revision、提交幂等状态。
3. 写入最小持久化操作记录（prepared），保存旧/新配置与输入信息；准备文件放在不被旧 WORK/RESULT 清理覆盖的受控任务运行区域。临时区域使用固定用途名，不把 job_id/时间戳加入路径。
4. 复用现有残留进程检查与终止规则，确认本地和相关远程执行不再占用原任务。
5. 清理旧尝试数据。当前 _reset_work_dir_in_place 的单项删除失败不能只警告后继续；须汇总并阻断排队。明确远程工作目录和本地镜像分别如何准备，不能保留会被执行器误用的远程旧状态。
6. 安装已准备的新输入，更新 JobSpec、来源、input hash、attempt_history、阶段/产物记录、有效配置及任务投影，清除旧错误、PID、进度、远程提交信息和检查点状态。
7. 所有必要文件落盘和数据库状态一致后，最后切换到 QUEUED，再允许调度器提交。
8. 返回新的尝试编号和修改摘要，刷新前端。

文件系统操作与 SQLite 无法组成一个原子事务。操作记录用于识别中断阶段：预清理失败保持终态；清理后失败保持不可调度并展示恢复原因，不能宣称旧结果已恢复；准备输入必须保留以支持同 request_id 的受控恢复。启动恢复逻辑只处理明确的未完成操作，不重复提交或自动清理不明目录。

新任务模式先准备输入及全部修改，最终仅调用一次 submit；将来源任务/尝试和参数差异写入 lineage/provenance，不覆盖原任务。

## 11. 审计与名称

每次尝试保存旧/新规范化参数、显式修改与实际生效变化、输入来源和 checksum、尝试编号、提交时间及执行方式。保留原有 attempts/attempt_history 兼容字段，不向其中混入旧结果对象作为新结果。

任务自定义名称、标签属于展示元数据，与计算参数分开。打开编辑不把自定义名称当作物理路径。原地重算保留 ID/目录；新任务由现有目录分配器生成目录。编辑参数的 provenance 与前期名称/结构标签整理功能协调，但不依赖其全部完成才能使用。

## 15. 完成定义

任意有效任务均能从队列进入对应编辑页面，以完整原配置为起点修改并提交；没有修改时语义保持，修改后执行器收到正确新输入与参数；原地/新建区别清楚；重试与失败不会造成重复提交或新旧结果混用；历史任务明确可查看和可迁移范围。交付包含全部工作流适配、UI 串联、必要后端闭环及验收证据。
