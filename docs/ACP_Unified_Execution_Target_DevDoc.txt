1. 背景与现状(已核实事实)
--------------------------------------------------------

目标:ACP 从"全局 local/remote 开关"演进为"统一执行目标选择"——
local 是一等 execution target,远程服务器是配置节点;统一的是
"节点描述与选择",执行机制仍各归其位 (JobRunner / RemoteJobRunner)。

现状事实(全部经代码核实):

  F1. 全局开关已存在:
      config `cluster.execution_mode` ('local' 默认 / 'remote')
      -> RemoteExecutionConfig.is_remote  (src/acp/scheduler/remote/config.py:160-163)
      -> JobManager._is_remote_enabled()  (src/acp/scheduler/manager.py:115-116)

  F2. 远程执行基础设施完整可复用:
      RemoteJobRunner / SSHConnectionPool / FileStager / CodeSyncer /
      RemoteCleanup / RemoteResultFetcher / NodeManager / script_gen

  F3. 分发漏斗单点:

            -> remote_runner.submit_remote(record, event_log)   # PENDING

  F4. 每作业字段现状:
      JobSpec.target_node (src/acp/scheduler/jobs.py:308) —— 仅远程选节点,

2. 设计原则(不可妥协)
--------------------------------------------------------

  P1. local 是一等 execution target,不是 remote 的反面。
  P2. 统一节点描述与选择,不统一执行器(不重造 Parsl/QCFractal)。
  P3. config-first,本地兜底:'local' 永远可用,远程是显式"升级"的能力。
  P4. 单点决策:_resolve_execution_target() 是全系统唯一选点。
  P5. fail-fast 而非静默回退:显式 target 不可用 -> 立即报错,绝不偷偷换节点。
  P6. 显式指定 vs 自动选择的失败语义严格区分。
  P7. 节点状态是动态的,节点配置是静态的,两者分离 (NodeState vs NodeSpec)。
  P8. 能力匹配优先于负载均衡;第一版不做 CPU/RAM/load 智能预测。
  P9. capability 三态(available/missing/unknown),unknown 不直接淘汰
      (module load 环境可能只在 LSF job env 提供二进制)。
  P10. 默认模式只影响未 dispatch 的作业;已 dispatch 作业生命周期
       完全由自身 execution provenance 决定。

3. 两条不可跨越的分界线
--------------------------------------------------------

  分界线 1:  default_execution_mode 只作用于 resolve_execution_target()
             ─────────────────────────────────────────────
             作业一旦 dispatch:
               poll / cancel / recovery 只读 job 自身 provenance
               (remote_job_id / result.execution_kind / result.execution_target)
               绝不再看服务默认模式。

  分界线 2:  transport health ≠ job lifecycle
             ─────────────────────────────────────────────
             SSH 断开 / 节点 offline 只表示:
               - 停止向该节点派新任务
               - 暂停对该节点的观测(不判失败、不 cancel、不 resubmit)
             只有 scheduler (bjobs) 明确判失败才更新 Job 状态。
             JobStatus=RUNNING 与 NodeState=OFFLINE 可同时存在。

6. 异常二分法
--------------------------------------------------------

  class ExecutionTargetError(RuntimeError):
      """永久:选择/配置错误,重试不会变好 -> fail fast."""

  class ExecutionCapacityUnavailable(RuntimeError):
      """暂时:目标有效但当前无法接新作业 -> 保持 STARTING 稍后重试."""

  决策表(逐行编码):
  ┌──────────────────────────────────────┬───────────────────────────────┬────────────┐
  │ 情况                                 │ 异常                          │ 处理       │
  ├──────────────────────────────────────┼───────────────────────────────┼────────────┤
  │ target_node=abc 不存在 / 禁用         │ ExecutionTargetError          │ fail fast  │
  │ target 处于 draining                 │ ExecutionTargetError          │ fail fast  │
  │ target 缺所需 capability (Phase 2)   │ ExecutionTargetError          │ fail fast  │
  │ target_node=compute-01 但满了         │ ExecutionCapacityUnavailable  │ 等 60s 重试│
  │ remote-auto 所有节点满               │ ExecutionCapacityUnavailable  │ 等 60s 重试│
  │ remote-auto 无任何 capable 节点       │ ExecutionTargetError          │ fail fast  │
  │ local 已 4/4                        │ ExecutionCapacityUnavailable  │ 等 60s 重试│
  └──────────────────────────────────────┴───────────────────────────────┴────────────┘

  _execute_submission 改造:
        except ExecutionCapacityUnavailable:
            # 保持 STARTING,event_log "waiting_for_capacity",sleep 60,retry
            # (复用现有 RemoteNodeUnavailableError 重试分支结构)
        except ExecutionTargetError:
            # 走现有 except Exception -> FAILED 分支(立即,带清晰 error)
        # RemoteNodeUnavailableError 保留向后兼容(等价 CapacityUnavailable)

7. 数据结构(NodeSpec / NodeState / NodeRegistry)
--------------------------------------------------------

  新文件:src/acp/scheduler/nodes.py (估算 <150 行)

  ExecutionMode = Literal["local", "remote"]   # 类型化,禁止裸 str

  @dataclass(frozen=True)
  class NodeSpec:
      name: str                                # "local" | "compute-01" ...
      kind: Literal["local", "remote"]
      enabled: bool = True
      host: str | None = None                  # 仅 remote
      max_jobs: int = 1                        # 必填 > 0;删除 None=不限(避免 ratio 特判)

  @dataclass
  class NodeState:
      status: Literal["ready", "busy", "offline", "draining"]
      running_jobs: int = 0
      last_checked: datetime | None = None
      message: str | None = None

  class NodeRegistry:
      def __init__(self, local_max_jobs: int, remote_nodes: list[RemoteNode]):
          self._local = NodeSpec(name="local", kind="local", max_jobs=local_max_jobs)
          self._remotes = [ _to_node_spec(n) for n in remote_nodes ]   # 映射,不新建配置
      @property
      def local(self) -> NodeSpec: ...
      @property
      def nodes(self) -> list[NodeSpec]: ...            # [local, *remotes],顺序=确定性 tie-break
      def require(self, name: str) -> NodeSpec: ...     # 显式查找;不存在/禁用 -> ExecutionTargetError
      def select_remote(self, required: frozenset[str] | None = None) -> NodeSpec: ...
          # Phase 2 前: 启用节点中 running/max 最小(用 NodeManager 计数)
          # Phase 2 后: capability 过滤 + load ratio(见第 11 节)

  字段减法(无数据来源,已从草案删除):
    - NodeSpec.priority / tags   (RemoteNode 无此字段;确定性 tie-break 用 YAML 顺序)
    - NodeSpec.max_jobs=None     (必填 > 0)
    - NodeState.queued_jobs      (NodeStatus 无数据来源)
    - LOCAL_NODE 常量            (改为 NodeRegistry.__init__ 内构造,local 仍完全自动)

  NodeState 来源:
    - local : 由 JobManager 推导(running_jobs = manager.count_local_running_jobs();
              running < max_jobs -> ready,否则 busy)。无心跳、无 SSH、无健康线程。

8. 执行目标解析 + 冲突校验
--------------------------------------------------------

  冲突校验(不是静默 target 优先;掩盖前端 bug 会违反 fail-fast):
  ┌──────────────────────────────┬──────────────────────┬────────┐
  │ execution_mode               │ target_node          │ 结果   │
  ├──────────────────────────────┼──────────────────────┼────────┤
  │ remote                       │ local                │ 400    │
  │ local                        │ compute-01           │ 400    │
  │ (无)                         │ compute-01           │ 允许   │
  │ remote                       │ compute-01           │ 允许   │
  │ local                        │ local / (无)         │ 允许   │
  │ (无)                         │ local                │ 允许   │
  └──────────────────────────────┴──────────────────────┴────────┘

  def validate_execution_request(spec: JobSpec) -> None:
      mode, node = spec.execution_mode, spec.target_node
      if mode == "remote" and node == "local":
          raise ExecutionTargetError("execution_mode=remote conflicts with target_node=local")
      if mode == "local" and node not in (None, "local"):
          raise ExecutionTargetError("execution_mode=local conflicts with target_node=<remote>")

  def resolve_execution_target(self, record: JobRecord) -> NodeSpec:
      spec = record.spec
      validate_execution_request(spec)
      if spec.target_node:                        # ① 实例指定(含 "local")
          return self.registry.require(spec.target_node)   # 不存在/禁用 -> TargetError
      mode = spec.execution_mode or self.default_execution_mode   # ② 偏好 -> ③ 服务默认
      if mode == "local":
          return self.registry.local
      return self.registry.select_remote()        # Phase 2 起带 required=

  优先级固定:target_node > execution_mode > server default。
  语义:
    execution_mode = remote  -> "资源类型偏好"(auto 挑一台合适的)
    target_node = compute-02 -> "资源实例指定"(必须这台,含 "local")
  两者保留,不合并。

  _submit_job() 最终形态:
      def _submit_job(self, record):
          target = self._resolve_execution_target(record)
          self._record_execution_target(record, target)      # 见第 9 节
          if target.kind == "local":
              self._admit_local(record)                      # M5: running < max 否则 CapacityUnavailable
              return self.runner.submit(record, ...)
          return self.remote_runner.submit_remote(
              record, event_log, target_node=target.name)    # M4: 已解析 target

      result = dict(record.result or {})

11. 能力感知调度(Phase 2)
--------------------------------------------------------

  任务需求来源 —— 直接复用现成资产,不自己推导:
      from acp.workflows.registry import get_workflow_entry
      required = set(get_workflow_entry(spec.workflow).requires_binaries or [])
      # 已由 remote/runner.py:1057 使用;禁止手写
      #   if workflow == "crest": return {"crest", "xtb"}

  节点能力:
    - local : 启动时 resolve_executable()(cccp.software,上轮交付)
              成功 -> {name: version};未检测到 -> 不写入(视为 unknown)
    - remote: 复用现有 _BINARY_PROBE_SCRIPT + _probe_required_binaries
              (remote/runner.py:997-1037, 1039+);positive detection 缓存入 NodeState

  三态能力:available / missing / unknown
    - SSH login shell which orca = None 不直接判缺失
      (LSF job env 可能 module load orca/6.1 提供)
    - 只缓存 positive detection;未检测到默认 unknown,不直接淘汰

  两级检查(不破坏 module 环境兼容):
    NodeRegistry 能力缓存          -> pre-filter / ranking
    RemoteJobRunner 探针(权威)     -> pre-submit 最终校验(现状保持)

  选择算法(第一版止步于此):
    1. enabled
    2. status == ready
    3. required ⊆ node.capabilities(unknown 视为通过 pre-filter)
    4. running_jobs < max_jobs
    5. min(running_jobs / max_jobs)
    6. YAML 配置顺序作确定性 tie-break
    不做:CPU load / memory / queue prediction / historical runtime / dynamic weights。

14. 验收清单(编码后逐条对照)
--------------------------------------------------------

  A. 概念拆分
    [ ] A1  cluster.execution_mode=local 且配置了 nodes:
            remote_runner 非 None(_remote_available,不再依赖 is_remote)
    [ ] A2  default_execution_mode 只出现在 resolve_execution_target() 内
    [ ] A3  JobSpec.execution_mode 类型为 ExecutionMode(Literal),非裸 str

  B. 生命周期路由
    [ ] B1  server 默认 local + job execution_mode=remote:
            _submit_job 走 remote_runner.submit_remote
    [ ] B2  该 job 的 _poll_job / cancel / recovery 均按 _is_remote_job 走远程
    [ ] B3  _is_remote_job 覆盖三种来源:remote_job_id / result.lsf_job_id /
            result.execution_kind == "remote"
    [ ] B4  server 默认 local + job 显式 remote:已提交后把服务端改成 remote,
            不影响该 job 生命周期;反之亦然

  C. 传输健康 ≠ 作业失败
    [ ] C1  remote poll 连续 3 次 SSH/bjobs 异常:JobStatus 保持 RUNNING,
            不 cancel,不 resubmit
    [ ] C2  恢复后 _poll_failures 清零并继续正常查询
    [ ] C3  节点 offline 时已提交作业不被判失败;仅 bjobs 判失败才更新

  D. 选点唯一
    [ ] D1  resolve_execution_target() 是唯一选点;submit_remote 收到
            已解析 target_node,不再内部 select_node
    [ ] D2  旧调用(submit_remote 不带 target_node)仍可用(向后兼容)
    [ ] D3  显式 target_node 不存在/禁用 -> ExecutionTargetError 立即失败,
            绝不 fallback 到其他节点

  E. 本地并发
    [ ] E1  local max_jobs=4 时第 5 个本地作业保持 STARTING 并 60s 重试
    [ ] E2  本地 running < max -> ready;>= max -> busy(NodeState 推导)
    [ ] E3  max_jobs 从 cluster.local.max_jobs 读取,绝不自动用 os.cpu_count()

  F. 异常语义
    [ ] F1  永久错误(TargetError)走 FAILED 立即;暂时错误(CapacityUnavailable)
            保持 STARTING 重试
    [ ] F2  冲突校验:remote+target=local / local+target=remote 均 400

  G. 数据与配置
    [ ] G1  NodeSpec 无 priority/tags/max_jobs=None;NodeState 无 queued_jobs
    [ ] G2  local 节点由 NodeRegistry 自动构造,用户无需配置 local node
    [ ] G3  provenance:record.result 含 execution_target + execution_kind;
            event_log 有 execution.target_resolved
    [ ] G4  remote 状态来自现有 NodeManager,list_nodes 的 is_remote gate 未改
