ACP 远程计算节点支持 — 详细开发计划

概述

为 ACP 平台添加远程计算节点支持，使 ACP Server 能通过 SSH/SFTP 将完整的 acp 作业提交到远程 OpenLAVA (LSF) 节点执行，并通过 LSF 日志实时监控状态。远程节点无需手动安装 ACP，代码通过 CodeSyncer 自动同步（SFTP 增量传输），支持所有工作流（conformer / nmr / mechanism / benchmark）。

核心约束

远程节点环境Python ≥ 3.10 + rdkit/numpy/openpyxl/pyyaml + OpenLAVA (LSF) + QC 软件齐全（Gaussian/ORCA/xTB/CREST）
代码部署CodeSyncer 自动同步：SFTP 增量传输 src/acp/（排除 api/scheduler）+ src/cccp/ + scripts/ 到 {remote_code_dir}/，无需 pip install
CLI 入口python -m acp.cli run <workflow>（LSF 脚本设置 PYTHONPATH={remote_code_dir}/src）
执行粒度整个 acp.cli run <wf> 命令作为一个 LSF 作业
工作流范围所有工作流（conformer / nmr / mechanism / benchmark / fake）
文件系统输入通过 SFTP 上传，所有结果保留在远程节点，不自动下载任何计算文件，仅支持用户按需单文件下载
监控方式LSF bjobs 状态 + SFTP 增量 tail stdout.log/stderr.log（不依赖 state.json）
轮询间隔30 秒
QC 配置远程节点自行配置 ~/.cccp.yaml 或环境变量，不同步本地 config/defaults.yaml
多节点支持多个远程计算节点，负载最低优先选择
远程文件保留180 天

新建 runner.py — 完整远程执行流程

  1. [新增] 检查/同步代码到选定节点（若 auto_sync=True 且代码有变更，调用 CodeSyncer.sync_code()）

    • 作业结束 → 读 .exit_code
  7. 不下载任何文件 — 远程结果保留在远程节点

根因

ACP Server 的 src/cccp/ 是一个分叉版本，与计算节点 /home//cccp/ 的权威版本存在结构性差异。CodeSyncer 将 ACP Server 的分叉版本同步到远程节点的 {remote_code_dir}/src/cccp/，LSF 脚本的 PYTHONPATH={remote_code_dir}/src 使同步版本在 import 优先级上覆盖了远程节点本地安装的权威版本（原始文件未受影响），导致：

  • 协议不匹配：ACP 版本无 lite/zero/benchmark 协议 → _validate_config 回退为 ext，输出 warning
  • DFT 阶段跳过：ACP 版本的 ConformerEngine（1280 行）在 ISOSTAT 聚类后直接 finalize，不调用 _run_shared_dft_handoff。远程权威版本（1733 行）的引擎在聚类后继续执行 DFT 优化/频率/单点/Shermo
  • API 不兼容：acp/cli.py 依赖 cccp.core.specs.ConformerWorkflowSpec（ACP 独有），远程版本使用 cccp.core.protocols.ProtocolSpec（不同 dataclass 设计）

  • is_remote_job(record) -> bool — 检查 record.result 是否含 node + remote_dir
  • resolve(record) -> (RemoteNode, str) — 从 record.result 提取节点名 + 远程目录，通过 RemoteExecutionConfig.get_node() 解析为 RemoteNode。无元数据抛 NotARemoteJobError，节点未配置抛 RemoteFileError
  • list_files(record) -> list[RemoteFileInfo] — SFTP 列远程作业目录（顶层）
  • file_exists(record, filename) -> bool — SFTP stat 检查文件是否存在
  • read_file(record, filename) -> bytes — SFTP 读取完整文件（中小文件）
  • stream_file(record, filename) -> Iterator[bytes] — SFTP 分块流式下载（64KB chunks），借连接池会话期间持有，迭代结束自动归还。大文件不占满内存

  • _safe_join(remote_dir, filename) — 路径拼接 + 遍历防护：posixpath.normpath 后校验结果仍在 remote_dir 下，../../etc/passwd 等逃逸路径抛 RemoteFileError

6B. 阶段 5B：本地磁盘保护（ACP Server 端）

Phase 5 仅保护了远程计算节点的磁盘。ACP Server 本地的 run_root（作业 work_dir + SQLite DB + 事件日志）无任何清理和保护——作业无限堆积，磁盘满时 OSError 被 bare except Exception 静默吞掉。本阶段为本地文件系统增加与 Phase 5 对等的生命周期管理。

本地 work_dir每个 job 的 events.jsonl / job.json / inputs/ 永久保留，无 TTL、无 retention、无定时清理
SQLite acp_jobs.db已完成/失败 job 记录无限堆积（scheduler/AGENTS.md 已标记为已知问题）

状态判定逻辑（一次 DB 查询 + 文件系统遍历）：

# 1. 查 DB 构建 {job_id: (status, completed_at)} 映射
status_map = {r.id: (r.status, r.completed_at) for r in store.list(limit=100000)}

# 2. 遍历 run_root/{project_id}/{job_id}/
for project_dir in run_root.iterdir():
    for job_dir in project_dir.iterdir():
        job_id = job_dir.name
        status, completed_at = status_map.get(job_id, (None, None))
        # 3. 按状态选保留期
        if status == 'failed':
            retention = policy.failed_days      # 90
        else:
            retention = policy.completed_days    # 30（含 completed/cancelled/孤儿）
        # 4. mtime + completed_at 取较新者判定过期
        age_ref = completed_at or _iso_to_epoch(job_dir.stat().st_mtime)
        if now - age_ref > retention * 86400:
            shutil.rmtree(job_dir)

def _cleanup_loop(self, stop_event: threading.Event):
    # 首次随机延迟，避免多实例同时触发
    first_delay = random.uniform(0, interval)
    if stop_event.wait(first_delay):
        return
    while not stop_event.wait(interval):
        if not self._cleanup_lock.acquire(blocking=False):
            continue  # 上一轮还在跑，跳过
        try:
            report = self._local_cleanup.full_cleanup()
            self._write_cleanup_log(report)
        except Exception:
            logger.warning("Background local cleanup failed", exc_info=True)
        finally:
            self._cleanup_lock.release()

14. 实施注意事项

14.1 远程节点一次性准备

  • Python ≥ 3.10
  • 依赖安装：pip install rdkit numpy openpyxl pyyaml
  • QC 软件：Gaussian 16, ORCA, xTB, CREST（路径在 ~/.cccp.yaml 或环境变量中配置）
  • OpenLAVA (LSF) 客户端
  • 无需安装 ACP — 代码由 CodeSyncer 自动同步到 {remote_code_dir}/

14.2 代码同步策略

  • 同步内容：src/acp/（排除 api/、scheduler/）+ src/cccp/（完整）+ scripts/run_g16_worker.sh
  • 不同步：config/defaults.yaml（QC 路径远程不同，避免覆盖远程配置）
  • 不同步：frontend/、tests/、pyproject.toml、bin/
  • 增量同步：本地记录每个文件的 mtime，同步时比较"本地当前 mtime vs 本地上次同步时 mtime"，若变化则上传。远程 mtime 不参与判断（SFTP 上传后远程 mtime 会变成上传时间，不可靠）。首次同步较慢，后续快速
  • 远程 PYTHONPATH：LSF 脚本设置 export PYTHONPATH={remote_code_dir}/src:$PYTHONPATH，无需 pip install

14.3 日志阶段解析（分阶段实施）

基础版本（阶段 1-8）：仅依赖 bjobs 状态 + .exit_code，日志 tail 仅作为原始文本展示，不做阶段解析。

增强版本（阶段 9）：实现 LogStageParser，通过正则匹配日志中的阶段标志行，更新 stage task 子阶段状态。具体标志行需要在远程节点配置完成后，通过实际运行作业验证。

14.4 安全

  • 密码仅通过环境变量传递，YAML 中不存储明文密码
  • SSH 日志脱敏：不输出密码、密钥内容
  • 远程文件保留 180 天后自动清理

14.5 StageTaskObserver 集成

远程作业创建简化的 remote_execution stage task，状态跟随 LSF 状态更新：

  • PEND → pending
  • RUN → running
  • DONE → completed
  • EXIT → failed

前端可显示"远程执行: PEND/RUN/DONE"，提供基本的进度反馈。

14.6 作业取消策略

发送 bkill <lsf_job_id> 后检查返回值：

  • 返回 0：取消成功
  • 返回非 0：取消失败（可能作业已结束），记录日志但不抛异常
