# IRC 输入与 TS 计算级别继承修改计划

**制定日期：** 2026-09-26  
**状态：** 核心约束已实施；待使用真实 ORCA 任务做端到端核验

## 实施记录（2026-09-27）

- 新建 `acp.calculations.irc.source`：仅解析已完成 BatchOptimize 的正式 TS 结构产物或 TS Mode 最终产物，并核对优化、频率、单一虚频、结构与有效方法。来源在远端时按需读取必要证据，不要求完整结果下载。
- 所有经调度器创建的 IRC 任务都通过同一个来源解析器生成规范化规格，锁定方法、基组、电荷和多重度；编辑预览、原地重算、普通提交及产物快捷提交沿用该校验。IRC 参数只保留方向、最大点数和步长。
- 运行器和 CLI 传递来源证明并核对输入 XYZ 校验值，结果报告保存来源身份、几何及频率证据摘要。工作台选择 TS 任务结果后显示继承级别与虚频；非法来源在预览和提交时给出原因。
- 当前 IRC 路径无法可靠复现独立色散、溶剂/网格或特殊电子态设置的来源会被拒绝。历史 IRC 结果仍可查看；缺乏证据的历史任务不能按旧自由输入方式重跑。
- 自动化校验已覆盖本地/远端来源、API、编辑预览、运行命令和前端契约。真实 ORCA 作业仍需在计算节点上核对实际输入文件及反应路径。

## 1. 目标与边界

IRC 只接受平台内已有任务正式产出的、经过频率确认的 TS 最终结构。提交时由服务端从来源任务的实际有效配置生成 IRC 方法，用户不得另选或覆盖电子结构级别。IRC 仍保持独立任务；方向、最大步数、步长、计算资源可单独设置。

“方法一致”指势能面相关的实际有效设置一致：计算引擎、方法/泛函、基组或复合方法、溶剂与色散、电子态、总电荷和多重度，以及会改变能量/梯度的其他设置。优化器收敛参数、IRC 步长和最大点数不要求相同。BatchOptimize 的单点能与热力学级别不能作为 IRC 级别。

## 2. 现状问题

- `POST /jobs` 可直接创建 `irc`，输入可以是任意结构路径，方法可独立填写；`input_role=transition_state` 只是声明。
- `POST /jobs/{job_id}/artifacts/{artifact_id}/run-irc` 只确认 `structure` 产物及 TS 标签，随后复制源任务的整个 `spec.method`；未验证该产物来自收敛的 TS 优化并通过频率检查，也未抽取该条 TS 实际使用的级别。
- BatchOptimize 对每个角色解析方法；TS 优化和频率共用方法/基组，但单点能可不同。直接复制任务配置不能证明 IRC 使用了 TS 级别。
- 工作台的 IRC 方法面板允许选择方法；TS 产物输入仍是自由文本，和来源任务没有强绑定。
- CLI `acp run irc` 同样允许任意 `--input`、`--method`、`--basis`，可绕过 UI 限制。

## 3. 权威来源契约

新增 `IrcTsSource` / `ResolvedIrcLevel` 只读解析服务。输入仅为 `source_job_id + source_product_id`（或等价的受控 source UID），不接受外部绝对路径或仅凭 TS 标签。解析服务必须：

1. 从任务数据库读取来源任务，要求来源为已完成的 `BatchOptimize` TS 条目或 `tsmode` 正式最终 TS 产物；旧版来源只有在能验证全部必要证据时才允许使用。
2. 在 `RESULT/result_manifest.json` 中定位指定结构产物，并关联同一条目的频率产物、优化/频率状态及证据；要求优化收敛、频率成功、恰好一个负频，结构与频率属于同一几何/条目。仅有 `TAG: TS` 不足以通过。
3. 从 `effective_config.json`、每条目 provenance 与实际计算记录提取该 TS 的有效优化/频率级别。若两步势能面设置不一致、来源缺关键设置或无法证明对应关系，返回明确的不可用原因，不静默采用默认 IRC profile。
4. 记录来源任务/产物 ID、任务尝试次数、结构与频率文件校验值、有效级别指纹及解析版本。提交时将几何快照复制到 IRC 任务输入区，避免后续源任务重跑改变输入。

可在 TS 产物 manifest 中增补 `ts_validation_v1` 与 `electronic_level_v1` 元数据，存每条目的收敛、虚频、方法及几何关联。旧任务以只读解析器恢复证据；不能恢复时提示重新执行或明确选择可验证的 TS 结果，不回填猜测值。

## 4. 提交与执行约束

- `POST /jobs`、产物快捷提交接口、编辑后重算、复制任务、CLI 和调度器共用一个 IRC 提交校验/规格生成函数。请求中的方法级别字段对 IRC 不再作为权威值；若客户端传入且与来源不符，直接拒绝并指出冲突字段。
- IRC `JobSpec.input` 保留来源身份与快照路径；`JobSpec.method` 写入规范化的继承级别和 IRC 专属参数。服务端在创建任务时校验一次，在启动前核对快照与级别指纹，失败则停止执行并给出具体原因。
- 运行器仅使用规范化后的级别，禁止 `method.method`、`method.functional`、`levels.irc.method` 等多处优先级覆盖。正确传递电荷、多重度、溶剂及电子态到 ORCA；执行产物记录实际 IRC 级别与来源指纹。
- 来源文件在远端时通过现有受控获取/快照机制处理，不将源任务机器上的绝对路径直接交给其他节点。

## 5. 工作台交互

- IRC 输入页改为“选择已验证 TS 任务结果”，列表只显示符合契约的最终 TS 产物；不可用条目可展示原因，如“未做频率”“虚频数不为 1”“计算级别记录不完整”。
- 方法面板展示从 TS 继承的只读摘要，并标明来源任务、条目、优化/频率级别；移除 IRC 方法和基组下拉选择。只保留 IRC 方向、最大点数、步长与资源设置。
- 从 TS 结构查看器发起 IRC 时使用同一个来源解析接口，不再通过自由文本传结构路径。预览与最终提交返回相同的校验结果。

## 6. 实施顺序

1. **契约与来源解析：** 实现 `IrcTsSource`、有效级别标准化、证据与指纹，扩展 BatchOptimize/tsmode 产物元数据；明确旧任务判定。
2. **后端强制校验：** 统一所有提交入口，阻止任意 XYZ/标签伪装、方法覆盖及缺证据来源；生成任务快照。
3. **执行对齐：** 收拢 runner/CLI 的方法解析，核对实际 ORCA 输入与源 TS 级别；写 IRC provenance。
4. **前端调整：** TS 结果选择器、只读级别摘要、不可用原因和提交错误提示。
5. **兼容与验证：** 旧 IRC 任务保持可查看；对旧任务的重跑/编辑使用新约束，不能验证时拒绝。更新文档和回归测试。

## 7. 验收用例

- 已完成且频率恰好一个负频的 BatchOptimize TS 可发起 IRC；TS 与 IRC 的实际 ORCA 势能面设置逐项相同，单点能级别不干扰。
- `opt_only`、INT、PES 候选、手工 TS 标签、未收敛 TS、零个或多个虚频、缺失/不匹配频率产物均不能提交。
- 伪造的来源 ID、跨条目频率、已修改的几何或频率文件、客户端强行改方法/基组/电荷/溶剂均被拒绝。
- 多条目 BatchOptimize 必须绑定正确的 TS 条目；`tsmode` 最终 TS 按同一规则验证。
- API、CLI、编辑后重算、快捷提交和前端选择器给出一致结论；已有 IRC 结果仍可读取。
