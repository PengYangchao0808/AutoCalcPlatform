# ACP 新建任务与候选管理整合方案

日期：2026-09-23  
状态：实施设计；本次仅新增方案文档，未修改业务代码。  
依据：用户提供的候选库、新建任务截图，以及本轮两版交互示意。

## 1. 目标与边界

将候选管理完整纳入“新建计算任务 → 选择输入”，主工作台聚焦项目、任务列表和任务详情。通过紧凑顶部、统一列表、有效的右侧详情区减少空白和重复操作，同时保留候选评估、标签、重命名、批量操作、垃圾箱及来源追溯。

本期交付包含：入口迁移、第一步布局、候选管理、垃圾箱、本次输入清单、三步向导视觉统一、编辑重算兼容、状态同步与验收。计算工作流参数、调度逻辑及量化程序调用保持原契约。第二、三步调整布局和摘要，不重新定义计算语义。

## 2. 已核实的现状

- `frontend/ACP_Workbench_v2.html` 同时保留独立候选库和新建任务来源面板；存在两个 `openCandidateLibrary` 及 `closeCandidateLibrary` 定义，后定义覆盖前定义。迁移必须删除重复路径，不能继续在文件尾部追加覆盖。
- `ACPSourcePicker` 已具有预览焦点、稳定 UID 选择、分页、搜索、筛选、批量标签和垃圾箱状态切换能力，可复用。
- 现有紧凑列表的 `⋯` 按钮直接调用 `onTrashItem`，不是展开菜单。应改成真正的菜单，点击 `⋯` 本身不得产生数据变更。
- 旧代码引用了 `ACPCandidateInspector`，但当前前端中未发现对应实现或脚本载入。不得以它已可用作为实施前提；新详情组件应显式实现，并复用现有 API。
- 后端已有 active/trash 状态、状态 revision、评估记录、候选版本、使用记录和 purge tombstone。
- 现有评估枚举为 `unreviewed / recommended / review / not_recommended`。示意中的“已确认”仅为占位，应正式改为“推荐”，不得将人工推荐等同于计算验证通过。
- 现有新建任务内移入垃圾箱后，会将已载入输入标为 trash 并阻断提交。新设计对本窗口主动移除改为成功后同步移出输入；外部变化仍保留失效项并阻断提交，避免无提示改变任务。
- 当前测试有“必须保留候选库主导航按钮”的旧断言，需替换为新信息架构契约，而非通过保留隐藏旧入口绕过测试。

## 3. 页面入口与信息架构

### 3.1 主工作台

移除主工具栏“候选库”按钮及独立弹窗。保留“新建任务”作为创建和输入管理统一入口。主界面原有项目选择、任务查询、状态、详情区不增加候选卡片。

能量、轨迹、振动、结构查看器继续保留“保存为候选”这一产出动作；不在查看器内新建或提交任务。保存成功提示候选可在“新建任务 → 候选结构”中找到。

### 3.2 新建任务第一步

标题行：新建计算任务、目标项目、关闭。  
步骤行：① 选择输入 → ② 配置计算 → ③ 检查并提交。  
来源导航：候选结构 / 任务结果 / 结构输入 / 上传文件。

- 候选结构：保存下来的候选，按真实 `source_kind=saved_candidate` 分类。
- 任务结果：其他可复用任务结构，包括 final、partial_result 及可读的历史来源；partial_result 明确标注“阶段产物”，不能假定来源任务已经完成。
- 两个来源共享同一个结构库、身份、状态、元数据和垃圾箱，不能创建两份数据。
- “候选结构”与“任务结果”是查询视图，不按标题是否含 candidate/TS 等文字判断。
- 垃圾箱从“更多管理”进入，覆盖当前来源项目的全部结构库条目，并标记来源类别；不会因切换两个来源页而漏掉已移除条目。
- 任务结果同样保留现有结构条目管理能力，右侧标题用“结构管理”；移除仍只影响可选条目，不删除计算任务和文件。

首次打开默认候选结构；记住用户上次使用的来源页。某一来源为空时显示明确空态和“查看任务结果／上传结构”入口，不自动跳页。

### 3.3 项目作用域

标题栏的“目标项目”决定新任务归属。列表默认浏览目标项目，筛选区允许选择其他来源项目或全部项目；明确显示“来源范围”，不能与提交目标混淆。

切换目标项目默认将来源范围回到该项目；保留已选输入并标记跨项目来源，不静默清空。原有禁止修改项目的编辑重算模式保持锁定。

垃圾箱恢复和彻底移除必须按条目真实项目校验。全部项目视图允许选择具体条目操作，但不提供“清空全部项目垃圾箱”。`null` 项目不得被前端当作当前项目使用。

## 4. 布局与视觉规格

### 4.1 桌面布局

- 对话工作区宽度建议 `min(1440px, calc(100vw - 48px))`，最大高度 `calc(100dvh - 48px)`。
- 标题区约 64px，步骤区约 44px，底部操作区约 64px；减少目前顶部重复大标题和说明。
- 内容为左右两栏，初始 60:40；右栏建议 360–480px，可拖动分隔线。缩放比例只保存为界面偏好。
- 左栏：来源导航、搜索、筛选/排序/分组、批量操作条、列表、分页。
- 右栏：预览、详情/管理、本次输入。预览建议 240–300px 高，低屏幕高度下可压缩到约 200px。
- 列表与右栏内容各自滚动；标题、步骤和底部操作保持可见。避免整个弹窗再出现一层重复滚动。
- 两栏顶部对齐；右侧通过信息组织利用空间，不使用等高空卡片填满底部。

### 4.2 响应式

- 宽屏按 60:40；中等宽度降低外边距，右栏最小约 320px。
- 视口小于约 900px 或分栏最小宽度不满足时上下排列，预览和输入清单可折叠。
- 1366×768、1440×900、1920×1080 为桌面重点验收尺寸；补充 768px、390px 及 200% 缩放。
- 文字和控件通过换行、折叠与布局变换适配，不通过整体缩小页面解决。

### 4.3 视觉系统

沿用 ACP 深色风格，背景建议页面 #0D141C、工作区 #121C28、浮层 #182434，边界 #283649；正文 #E5ECF4，辅助文字 #A5B3C4，交互蓝 #6EA8FE。以实际对比度检查调整，不视为已完成无障碍认证。

- 统一字体栈：system-ui / Segoe UI / Microsoft YaHei / sans-serif，排除列表出现不同衬线字体。
- 标题 20–22px，正文 14px，辅助信息 12–13px；权重主要为 400/500/600。
- 间距采用 8/16/24px，紧凑工具栏内部可用 4px；按钮高 36–40px，触屏有效点击范围至少约 44px。
- 对话框圆角 14–16px，按钮/输入框 6–8px；减少大胶囊按钮、渐变及多层描边。
- 蓝色用于当前步骤、预览焦点、选中输入和主行动；红色文字用于移除操作，彻底移除确认才使用更强的危险强调。
- TS/INT、评估和可用性同时有文字，不仅依靠颜色表达。

## 5. 列表、预览与右侧详情

### 5.1 列表

每行约 60–68px，紧凑模式约 48–56px。首行显示勾选框、显示名称、TS/INT、小型更多菜单；次行显示候选编号、评估、必要的可用性信息。来源任务分组后不在每一行重复长任务名。

默认按来源任务分组、最新产出排序；保留不分组及现有排序。搜索支持名称、来源任务、编号和标签。筛选默认收起，启用条件在工具栏显示并支持清除。

长名称可截断，完整名称在右侧换行显示并支持复制。无名称时使用候选编号或结构名回退，不能显示 undefined。

### 5.2 预览与勾选分离

- 点击行主体只切换预览，浅色背景/侧边标记表示预览焦点。
- 勾选表示纳入本次输入。取消勾选只移出本次输入。
- 点击菜单、复选框、链接不得触发行预览或其他操作。
- 首次加载自动预览第一条可预览结构，不自动勾选；空列表显示空态。
- 搜索、分页、分组变化保留输入；显示“已选 N 项，其中 M 项不在当前列表”。
- 批量删除作用域明确为当前可见列表中勾选的 K 项，按钮附近显示数量，不隐式操作隐藏选择。需要处理其他页时先查看所选或切换页面。
- 垃圾箱使用独立操作勾选集合，绝不将垃圾箱勾选加入计算输入。

### 5.3 结构预览

工具栏提供重置视角、放大、原子编号；旋转直接在视图内操作。各来源切换时清理旧模型，先显示新条目身份和 loading，再装载几何。

必须保留 unselected/loading/loaded/pending_fetch/failed 状态；pending_fetch 提供获取结构操作，failed 提供重试，不能将读取失败伪装成无候选。每次请求带 token 或取消信号，旧响应不得覆盖新焦点。

严格使用 `scheduleViewerFraming` / `frame3DViewer` / `disposeViewerFraming`：布局尺寸稳定后取景，普通 resize 保留用户相机；放大和收起后正确重排。

### 5.4 详情与管理

默认展示完整名称、角色、来源任务、编号/帧、评估、标签。电荷、多重度、频率等仅在有对应可靠来源时展示；缺失用“未提供”，不得补成 0/1。能量如显示，必须带单位、计算级别及比较范围，不跨不同体系/级别直接排序比较。

管理功能：重命名、编辑标签、评估及备注、移入垃圾箱。基础信息编辑按明确的“保存”动作提交，保存中有状态；切换条目遇到未保存编辑先提示处理。

评估用四种现有状态：未评估、推荐、待复核、不推荐。保留原因、备注、适用范围和版本关联；历史详情按需展开。推荐不等同于验证通过，不推荐不等同于垃圾箱。

来源任务通过链接打开详情；先保存本次输入草稿，返回后仍可继续创建。

## 6. 本次输入与任务草稿

右下角显示独立输入清单：名称、来源、角色、几何加载/校验状态、“移出本次输入”。条目可定位到预览；输入多时局部滚动，顶部计数一直可见。

- 同一 source_uid 的相同版本去重；同一来源有新版本时提示重新确认，不能静默替换用户已选几何。
- 结构输入和上传与库来源统一进入输入清单，但仅本地导入项没有结构库垃圾箱操作。
- 勾选先创建 pending 输入引用，几何载入成功变为 ready；失败保留 failed 行以便重试或移出，不能计为就绪输入。
- 设置角色、电荷、多重度以及编辑几何属于本次任务参数，不隐式写回候选库；对来源元数据修改另走管理保存动作。
- 同一窗口切换页签、筛选、垃圾箱、向导步骤保持草稿。关闭使用“关闭并保留草稿”，提供明确“清空草稿”操作。
- 草稿优先在当前页面内存保存，不承诺跨刷新保留上传文件；刷新恢复机制不纳入本期默认功能。再次进入时恢复内存草稿，成功提交后清空。
- 明确区分“候选管理已经保存的变化”和“尚未提交的任务草稿”；关闭新建任务不会回滚前者。
- 普通结构工作流要求至少一个 ready 输入才可继续；PESsearch、TSMode 等需要 manifest/Hessian/特定来源契约的工作流按目录和现有适配器校验，不能用通用 XYZ 判断替代。

## 7. 垃圾箱完整交互

### 7.1 入口

1. 行末 `⋯ → 移入垃圾箱`。
2. 右侧“候选管理/结构管理 → 移入垃圾箱”。
3. 当前列表有勾选时，出现“当前列表已勾选 K 项 → 移入垃圾箱”。

移入是可恢复操作，无例行二次确认。危险行为是从垃圾箱彻底移除，需确认。

### 7.2 主动移入流程

点击后冻结此次目标 UID/版本/revision 列表并禁用重复提交；调用服务器状态更新。成功项从正常列表消失，并同步移出本次输入。提示“已移入 K 项，并从本次输入移除 M 项”，提供撤销、查看垃圾箱。

失败项保持原状；显示成功、失败、冲突各自数量，保留失败清单和重试入口。不得使用 Promise.all 首个拒绝后把整批当作未执行或全部成功；使用有限并发、逐项结果归集。

当前预览项被移除时定位到相邻可用条目，列表为空显示明确空态。列表总数、分组、垃圾箱数量和输入计数同步刷新。

### 7.3 撤销

撤销是向服务端请求恢复 active，不只是恢复前端行。保存最近一次成功移入操作的结果 revision 与被移除的输入快照，通知区保留撤销直至关闭通知、下一次结构库变更或离开本次创建会话。

只有服务端恢复成功且版本仍一致时，恢复其原有输入快照；若几何/可用性变化，恢复候选但提示重新选择。撤销冲突显示最新状态，不强行覆盖其他窗口操作。普通“恢复候选”与撤销不同，前者不自动加入输入。

### 7.4 垃圾箱视图

从更多管理进入，复用列表和右侧布局；显示“垃圾箱”、计数、“返回结构列表”。退出恢复进入前的来源页、筛选和滚动位置。

行菜单和右侧提供恢复；批量工具栏提供恢复所选、彻底移除所选。无选中时不展示批量破坏性操作。进入垃圾箱不影响本次输入清单。

垃圾箱条目不能加入输入，不能进入正常提交；恢复后回到对应来源分类。评估、标签、版本等软删除前的信息保持。

### 7.5 彻底移除与清空

确认对话框显示目标数量、项目、若干名称，并明确“无法通过垃圾箱恢复；来源任务和原始文件保留”。只调用结构条目 purge，不调用任务 purge。

“清空当前项目垃圾箱”保留在垃圾箱更多菜单中，限定明确的单个项目。确认前解析该项目当前垃圾箱 UID 集合，确认后提交同一集合，避免等待期间新增条目也被删除；不能通过 source_uids=null 扩大确认范围。

现有 tombstone 阻止相同 geometry_hash/source_revision 被重新索引；新几何或新来源 revision 仍可能产生新版本。文案不能承诺该来源永远不再出现。

### 7.6 外部变化

若条目被其他窗口移入垃圾箱、删除或更新版本，本次输入标为“已失效/版本已变化”，保留可见提示并阻断相应提交。用户选择移出、恢复并重新校验或重新载入。服务端提交校验始终保留，不依赖前端缓存状态。

## 8. 第二、三步的一致性

配置计算：沿用目录驱动的工作流、方法和参数构造器；顶部仍为同一项目与步骤。输入清单改为紧凑摘要，可返回第一步调整；不在右栏重新放一套结构库。

检查并提交：显示项目、工作流、输入数量、计算级别、资源和阻断问题。提交前校验最新来源状态/版本、工作流输入能力及未完成载入。任务创建结果明确反馈；发生部分创建失败时保留未成功项，沿用现有防重放机制。

编辑重算/复制为新任务共享布局，但保留原有工作流锁、项目锁、来源差异、preview_fingerprint、source_revision、request_id 及 preview→确认链。新建来源切换不得清除原编辑输入或越过锁定条件。

## 9. 前端实现组织

建议新增 `frontend/js/task_input_workspace.js` 与 `frontend/css/task_input_workspace.css`，承担工作区装配、状态和局部样式。建议新增 `frontend/js/candidate_details.js`，显式实现可测试的详情/评估组件。

复用 `structure_source_picker.js` 的查询、分页、筛选、标签及选择；不另写第二个库列表。通过适配器与现有 wizardStructures 连接，向导输入以一个状态源为权威，不能维持两套可独立变更的已选数组。

工作区状态至少包括 targetProjectId、sourceScope、sourceTab、libraryView、query、previewRef、inputEntries、trashSelection、pendingOperations、undoOperation。预览、输入、垃圾箱勾选相互独立。

HTML 仅负责挂载和现有向导接线。迁移现有加载、几何解析及提交适配器；删除重复候选库函数、旧弹窗、无用全局变量、监听器和样式。保留非本期页面使用的共享函数，避免过度删除。

状态更新用明确事件：预览变化、输入增减、候选状态更新、元数据保存、版本失效。事件携带 UID、版本/revision、操作来源；反向更新列表复选框时避免递归回调。

界面文案进入现有中英 i18n。图标配可读名称；菜单支持键盘、Esc、点击外部关闭及焦点归还；状态结果 aria-live 提示。

## 10. API 与数据契约

以 `/api/v2` 为前缀复用：

| 能力 | 接口 | 要求 |
|---|---|---|
| 列表 | GET `/structure-sources` | 保留服务端搜索、分页、分组、项目过滤 |
| 元数据 | PATCH `/structure-sources/{uid}/metadata` | 使用元数据 revision |
| 批量标签 | POST `/structure-sources/batch-metadata` | 逐项结果与冲突 |
| 详情 | GET `/structure-sources/{uid}/candidate` | 版本、评估和使用信息 |
| 移入/恢复 | PATCH `/structure-sources/{uid}/candidate/status` | status=trash/active，expected_revision |
| 评估 | POST `/structure-sources/{uid}/candidate/assessments` | 正确版本、原因与范围 |
| 彻底移除 | POST `/structure-sources/trash/purge` | 明确项目与目标 UID 集合 |

必要的小范围扩展：为列表和 facets 同步增加可选 `source_group=candidate|task_result` 过滤，分别对应 saved_candidate 与其他可读 source_kind（包括空历史类型）；与旧 source_kind 参数同时提供时明确返回 422，避免歧义。旧调用不带新参数时保持原行为。

分类在服务端查询分页前执行，不能仅过滤当前一页；结果总数、分组数量、facets 必须与条件一致。不增加新的候选表，不复制候选，不预设需要数据库迁移。

409 状态冲突与元数据冲突按实际响应形状解析；刷新条目后提示用户，禁止无条件自动重试覆盖。后台结构状态与 UI 推荐评估保持独立。

## 12. 验收标准

### 功能与数据

1. 主工作台无独立候选库入口；所有管理能力可从新建任务到达。
2. 四类来源输入正常；候选/任务结果分类完整、总数正确、无分页漏项。
3. 点击预览不改变输入数；勾选、取消、移出操作一致，无重复添加。
4. 搜索/分页/切页保留输入，隐藏选择计数正确，批量移入只作用于明示目标。
5. 单个/批量移入成功后同步移出输入；失败项不丢失，部分成功清晰可重试。
6. 撤销真实恢复状态与符合条件的输入快照；普通恢复不会自动加入计算。
7. 垃圾箱选择不能提交；彻底移除需要确认；取消确认没有任何写入。
8. 来源任务、原始轨迹和已有计算结果未被候选清理删除。
9. 相同版本不会被索引重新创建；新版本按现有 tombstone 语义处理。
10. 当前项目、跨项目、全部项目查询与 purge 目标一致；不能清空范围外条目。
11. 409、404、网络失败、外部移除、版本变化均有确定行为；服务端继续拒绝失效输入。
12. 重命名/标签/评估持久化；关闭向导不会回滚已保存管理变化。
13. 新建、复制、修改参数后重算及特定工作流来源契约均保持有效。

### 视觉与可用性

14. 重点桌面尺寸及 200% 缩放下底部可操作，无横向溢出和遮挡。
15. 长名称、200 个选择、空列表、长分组和多标签均可阅读。
16. 右侧预览/详情/输入清单均有实际内容或清晰空态，无孤立大块空框。
17. 切换 A→B 时 A 的迟到请求不覆盖 B；放大/缩小后相机和尺寸正确。
18. 菜单、勾选、确认对话框可键盘操作，焦点可见且返回位置合理。
19. 正常、加载、远程待获取、失败、无匹配、垃圾箱空态均有明确文案。
