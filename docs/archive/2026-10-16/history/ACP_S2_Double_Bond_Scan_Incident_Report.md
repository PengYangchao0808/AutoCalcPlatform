# S2 双键同步扫描能量曲线异常问题报告

**报告日期**：2026-09-05  
**事故对象**：`20260904_115655_001_PESsearch`（来自用户截图）  
**问题级别**：P0 / 科学结果不可直接使用  
**当前结论**：已定位高可信主因；原始事故任务的完整输入、ORCA 输出和 `pes_profile.json` 不在当前工作区，故个别数值仍需用原始任务产物复核。

## 1. 技术摘要

截图中的曲线不是正常的“能量面上有起伏”现象，而是扫描约束和结果质量控制同时失效后的表现：

1. 截图对应的事故版本将 ORCA 内部坐标约束写成 `{ B i j C value }`。ORCA 6.0/6.1 官方语法是 `{ B i j value C }`，即目标值必须位于末尾 `C` 标志之前。当前工作区的未提交改动已经把渲染改为正确顺序，但该修正发生在截图任务之后，尚未成为提交历史的一部分。
2. 双键同步扫描虽然会在每一帧构造两条约束，但完成判定只依赖 ORCA 优化是否返回成功；没有把每条约束的 `target - actual` 残差作为硬门禁。因此“优化收敛”可能被误当成“扫描坐标按目标推进”。
3. S2 能量图使用第一条扫描坐标的实际值作为横坐标，并按原始帧序直接连线；没有检查实际横坐标是否单调，也没有把第二条双键的偏差在图上显式呈现。只要约束失效或坐标漂移，就会出现截图中前段近似竖直、回折、跨越连接的异常视觉结果。
4. 候选点推荐同样只使用第一条坐标和第一条成键对，对“双键同步扫描”的二维坐标信息没有完整建模。因此当前图上的 `TS-001`、`INT-015` 不应直接作为后续 BatchOptimize 的可信初猜。

**结论**：首要修复对象是事故版本的 ORCA 约束渲染；首要防复发对象是 S2 的“约束残差校验 + 曲线可用性门禁”。仅修改前端连线或平滑曲线不能修复科学结果。

## 4. 根因链路

```text
前端选择四个原子
  → 生成两条同步 distance 坐标，共用 λ 和帧数
  → 每帧进入 ORCA constrained_optimize
  → 事故版本写入 { B i j C value }
  → 目标坐标未可靠施加 / 实际坐标发生漂移
  → ORCA 返回“优化完成”，但应用不校验 target-actual 残差
  → profile 仍然收集能量与帧
  → 图表以第一条 actual_coordinate 为 x，按帧序连线
  → 非单调回折被绘制成异常曲线，并参与 TS/INT 推荐
```

这里要区分三个层次：

- **计算层**：约束语法错误是最可能使事故数据失真的直接原因；
- **数据层**：缺少约束残差和双坐标完整性门禁，使坏帧能够进入 `pes_profile.json`；
- **表示层**：横坐标投影和原始帧序连线把问题放大为截图中的回折曲线。

## 5. 范围与指标定义

### 5.1 双键同步扫描的预期定义

双键扫描应满足两条距离约束在同一进度参数 `λ` 下同步推进：

```text
q1_target(λ) = q1_start + λ · (q1_end − q1_start)
q2_target(λ) = q2_start + λ · (q2_end − q2_start)
λ = frame_index / (n_points − 1)
```

每个收敛帧都必须同时满足：

```text
|q1_actual − q1_target| ≤ tolerance_1
|q2_actual − q2_target| ≤ tolerance_2
```

### 5.2 当前实现实际使用的指标

- 能量：优先使用全部完成的单点能，否则回退到扫描优化能量；
- 相对能量：相对首个非空能量，不是相对全局最低点；
- 图表横坐标：优先使用第一条 `actual_coordinate`，缺失时才回退到第一条 `target_coordinate`；
- 双坐标详情：两条 `target_coordinates` / `actual_coordinates` 会写入帧记录，但没有形成独立质量指标；
- 收敛状态：主要由 ORCA 返回成功及单点状态决定，不等价于“约束残差合格”。

## 6. 定位依据与复现证据

### 6.1 ORCA 约束语法核验

ORCA 6.0/6.1 官方手册的约束格式为：

```text
{ B N1 N2 value C }
{ A N1 N2 N3 value C }
{ D N1 N2 N3 N4 value C }
```

参考：[ORCA 6.0 Manual — Constrained Optimizations](https://www.faccts.de/docs/orca/6.0/manual/contents/typical/optimizations.html)；[ORCA 6.1 Manual — Geometry Optimizations](https://www.faccts.de/docs/orca/6.1/manual/contents/structurereactivity/optimizations.html)。

事故版本的旧实现是：

```text
{ B 1 2 C 1.50000000 }
```

当前工作区未提交改动已经修成：

```text
{ B 1 2 1.50000000 C }
```

本地文件时间显示，该约束渲染修正约在 `2026-09-04 13:37` 修改；截图任务 ID 中的开始时间为 `2026-09-04 11:56:55`。这与“截图产生于旧语法、之后才修正”的时间关系一致，但仍应以任务目录内实际 `.inp` 文件为最终证据。

### 6.2 图表异常的合成复现

用一个非单调的实际坐标序列验证当前图表投影：

```text
x_in_frame_order = [1.45, 1.43, 1.42, 1.48, 1.56, 1.72]
y_in_frame_order = [0, -25, -52, -100, -131, -110]
x_is_monotonic   = False
```

当前前端会按这个顺序生成 `M/L` SVG path，而不是按目标坐标或扫描进度绘制。因此它必然表现为横坐标回退和回折连接；这与截图形态一致。需要强调：这个合成复现证明了“显示层如何放大异常”，不单独证明事故任务的原始 `x` 数值就是这组数值。

## 7. 修复和防复发建议

### P0：立即止损

1. 将 `20260904_115655_001_PESsearch` 标记为“结果待复核”，暂停使用其 TS/INT 结构。
2. 从原始运行节点保留：双坐标扫描请求 JSON、每帧 `.inp/.out`、`scan_frames/*.xyz`、`RESULT/pes_search/pes_profile.json`、ORCA 版本和完整 stderr/stdout。
3. 在确认事故版本确实使用旧语法后，使用当前正确的 `value C` 版本重新跑该双键扫描；不要对已有曲线做后处理后继续使用。

### P1：计算和结果质量门禁

1. 在 `calculations/pes` 增加双坐标帧验收函数：检查帧数、索引、有限数、两条 target/actual 是否齐全、每条约束残差是否在可配置阈值内。
2. 距离扫描默认建议使用可配置的约 `0.01 Å` 残差阈值；具体阈值应结合 ORCA 版本、优化容差和方法做集成校准，不应在报告中硬编码为科学常数。
3. 检查目标坐标方向与实际坐标方向；如果目标递增，实际坐标出现回退、重复或大步跳跃，应将 profile 标记为 `invalid`，禁止生成候选点。
4. `optimization_converged=true` 仅表示优化器收敛，不能代表约束满足；建议增加 `constraint_residual_ok`、`max_constraint_residual` 和 `invalid_reasons` 字段。
5. 当任一双坐标残差超限时，API 应返回明显的“扫描坐标失配”告警，前端不得只显示“已完成”。

### P1：图表和分析语义

1. 双坐标同步扫描优先使用显式 `λ` 或目标坐标作为横轴，并同时展示两条实际坐标的残差；不要静默把二维坐标状态压缩成第一条实际键长。
2. 如果保留一维能量曲线，应把横轴定义为“扫描进度/目标坐标”，把 `actual-target` 作为质量带或第二图层；发现非单调或残差超限时，整图显示“不可解释”状态。
3. 不建议简单按实际 `x` 排序来“修直”曲线，因为排序会破坏帧的计算时序并掩盖约束失效。应保留帧序、报告异常并阻断候选推荐。
4. 将“相对能量”改为更明确的“相对首帧能量”，或在图例/详情中展示 `reference_index`，避免用户把负值误认为归一化错误。

### P2：候选推荐和测试

1. 双键扫描的路径分析应传入两条 `forming_bonds`，候选评分至少要携带两条键的目标/实际值和残差。
2. 增加真实 ORCA 集成测试（按项目的 `--run-integration`/`--run-slow` 规则门控）：生成 3–5 帧双坐标输入，检查 `.inp` 字符串、两条约束均被 ORCA 识别、输出实际距离与目标一致。
3. 增加合成回归测试：非单调 `actual_coordinate`、第二坐标严重偏离、重复坐标、缺失坐标时，profile 必须进入不可用状态，且前端不能产生正常候选标记。
4. 当前工作区中对约束语法和双键选择逻辑的未提交改动应在重新跑通真实 ORCA 集成测试后再提交；报告本身没有覆盖或回滚这些用户现有改动。

## 8. 限制与待补证据

当前环境中没有找到截图任务 `20260904_115655_001_PESsearch` 的原始目录，因此以下结论暂不能做到逐帧数值闭环：

- 四个实际原子索引及两条键的具体身份；
- 21 帧的完整 `target_coordinates` / `actual_coordinates` 表；
- 事故 `.inp` 中是否确实出现 `{ B ... C value }`；
- ORCA `.out` 是否报告约束解析警告、约束收敛信息或结构拓扑变化；
- 曲线默认使用扫描能量还是单点能量；
- ORCA 版本、扫描方法、单点方法和电荷/多重度。

拿到上述产物后，建议首先做三张审计表：

| 表 | 每帧必须包含 |
|---|---|
| 约束表 | frame、λ、q1 target、q1 actual、q1 residual、q2 target、q2 actual、q2 residual、converged |
| 能量表 | frame、raw Eh、reference frame、relative kcal/mol、energy source |
| 结构表 | frame、XYZ 路径、两条键长、拓扑/连通性、与前一帧 RMSD |

只有三张表同时通过，才允许把 S2 候选交给 BatchOptimize。

## 9. 最终判定

本问题应按“计算结果可信度事故”处理，而不是按“能量图显示 bug”处理。

- **直接主因（高可信）**：事故版本 ORCA 约束格式与官方语法不一致；
- **放行主因（已证实）**：应用没有验证双条约束的实际残差；
- **可见性放大器（已证实）**：图表用第一条实际坐标、原始帧序直接连线；
- **后续误判风险（已证实）**：TS/INT 推荐只按第一条键分析；
- **能量负值问题**：按当前“相对首帧”定义并非独立 bug，但语义需要改清楚。

在完成原始任务产物复核和修复后的真实 ORCA 重跑之前，截图中的能量曲线、TS-001 和 INT-015 均应视为无效候选。
