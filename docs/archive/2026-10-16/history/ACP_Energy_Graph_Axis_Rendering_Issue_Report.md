# ACP 能量图坐标轴无法持续显示问题报告

**报告日期**：2026-09-05  
**问题范围**：Workbench v2 的 `viewer-energy`，重点是 PESsearch/S2 扫描能量图  
**问题级别**：P1（严重影响结果阅读、坐标核对和候选点审查）  
**状态**：已确认问题现象与高可信渲染根因，尚未修复  
**证据**：用户提供的 1920×844 截图；当前工作区 `frontend/ACP_Workbench_v2.html`；定向测试结果

## 1. 问题摘要

ACP 当前能量图的坐标轴不是没有生成，而是和曲线一起放在一个固定尺寸的 SVG 中，再由一个受限高度且允许滚动的容器承载。视口高度不足时，坐标轴的底部区域被滚动容器和滚动条裁切，因此坐标轴无法在用户查看曲线时始终保持可见。

截图中最明显的表现是：

- 左侧纵轴线和部分纵轴刻度仍可见；
- 横轴基线、横轴刻度以及“扫描坐标”横轴标题没有在当前可视区域内完整显示；
- 图表右侧出现竖向滚动条，底部出现横向滚动条；
- 用户需要改变滚动位置或牺牲曲线可视范围，才可能看到被裁切的轴信息；
- 因而图表虽然有曲线和点，但当前截图不能完整回答“某个点对应什么扫描坐标、坐标范围是什么”。

这属于前端布局/裁切问题，不是能量数据丢失，也不是 PES profile 没有提供坐标。

## 2. 预期行为与实际行为

### 2.1 预期行为

在初始显示、窗口缩放、切换能量序列、选择帧、缩放、框选、平移和实时刷新后：

1. 横轴和纵轴的轴线、刻度值、轴标题应同时位于图表可视区域内；
2. 坐标轴应固定在图表视口的边缘，不能被内部滚动条遮挡或滚出视口；
3. 曲线可以缩放/平移，轴刻度可以随 domain 更新，但轴本身不能消失；
4. 图例、横向滚动条和结构查看器不应覆盖横轴刻度或横轴标题。

### 2.2 当前行为

在用户截图所示的 PESsearch 能量图状态下，坐标轴信息不完整：纵轴部分可见，横轴信息落入底部裁切区。图表的内部滚动条说明绘图内容尺寸已经超过了可用视口；坐标轴没有独立的固定层，因此它随 SVG 内容一起受到裁切和滚动影响。

## 3. 复现条件与步骤

### 已由截图确认的场景

1. 打开一个已完成的 PESsearch 任务；
2. 切换到“能量图”标签；
3. 在 Workbench v2 的常规桌面布局中查看扫描能量曲线；
4. 当中央查看区域的有效高度不足以容纳完整图表时，观察到横轴信息不在当前视口内，同时出现图表滚动条。

### 建议补充验证的状态

以下状态应作为同一缺陷的回归场景验证：

- 缩短浏览器窗口高度或收窄中央面板；
- 选择其他帧后触发图表重绘；
- 切换相对能量、扫描能量或单点能量序列；
- 使用缩放、框选和平移工具；
- 发生 `ResizeObserver` 重绘或任务实时数据刷新后观察坐标轴和滚动位置。

当前本地没有运行中的 ACP API 和截图任务数据，因此上述动态交互未在本地连接任务上逐项回放；静态代码证据和截图已经足以确认布局缺陷，但不能据此声称所有交互状态都以完全相同的方式触发。

## 4. 技术证据

### 4.1 坐标轴确实由前端生成

`energyGraphAxesMarkup(xDom, yDom)` 会生成：

- 5 条纵向刻度对应的水平网格线和纵轴刻度文本；
- 5 个横轴刻度文本；
- 左侧纵轴线；
- 底部横轴线。

对应代码：

- `frontend/ACP_Workbench_v2.html:6600-6620`：坐标轴 markup 生成；
- `frontend/ACP_Workbench_v2.html:6899-6904`：坐标轴组和 X/Y 轴标题被追加到 SVG；
- `frontend/ACP_Workbench_v2.html:6800`：能量图使用 `viewBox="0 0 1040 520"`。

因此，当前现象不是“后端没有返回横坐标”或“坐标轴逻辑未执行”。

### 4.2 当前布局使轴区域可被裁切

关键 CSS 为：

```css
.energy-chart-scroll {
  min-height: 0;
  overflow: auto;
}

.energy-chart-svg {
  width: 100%;
  min-width: 640px;
  min-height: 360px;
  height: 100%;
}
```

对应代码：`frontend/ACP_Workbench_v2.html:1025-1026`。

同时，图表面板的中间行是 `minmax(0, 1fr)`，查看器本身又位于固定工作台区域内：

- `frontend/ACP_Workbench_v2.html:930-946`：工作台使用受限高度和 `overflow: hidden`；
- `frontend/ACP_Workbench_v2.html:1000-1004`：图表面板使用 `auto minmax(0, 1fr) auto`；
- `frontend/ACP_Workbench_v2.html:1025-1026`：内部图表容器允许水平、垂直滚动。

SVG 的底部轴区域使用固定坐标：

- 横轴线位于 `H - pad.bottom = 448`；
- 横轴刻度文本基线位于 `H - pad.bottom + 23 = 471`；
- 横轴标题基线位于 `H - 17 = 503`。

当 SVG 的最小高度大于图表中间行的可用高度时，底部轴信息必然成为滚动内容的一部分；横向滚动条还会进一步占用或遮挡底部可视空间。当前实现没有独立的 sticky/fixed 轴层来保证这些元素留在视口内。

### 4.3 重绘会放大问题

`energyGraphUpdateChart()` 每次更新时直接替换图表容器的全部内容：

```javascript
scrollEl.innerHTML = energyGraphBuildSvg(energyGraphState.data);
```

对应代码：`frontend/ACP_Workbench_v2.html:6651-6656`。

这使图表在选点、切换序列、缩放、平移或尺寸变化后重新建立 SVG。若用户已经滚动到轴区域，重绘可能导致滚动位置被重置或重新落回轴区域不可见的状态，进一步造成“坐标轴不能永远显示”的体验。

## 5. 根因判定

### 直接根因（高可信）

坐标轴、曲线和标注共用一个固定 `1040×520` SVG；SVG 又被放入一个高度受限的 `overflow:auto` 容器。坐标轴没有独立的可视层，因此底部轴信息会随内容一起被裁切、滚动或被滚动条覆盖。

### 次级放大因素（已由代码确认）

1. `height: 100%` 与 `min-height: 360px` 同时存在，图表实际尺寸受父级剩余高度和最小高度共同影响；
2. 轴的底部 padding、横轴刻度和横轴标题都依赖 SVG 内部底部空间，无法脱离 SVG 视口固定显示；
3. 图表重绘通过 `innerHTML` 全量替换 SVG，可能重置用户为了查看轴而产生的滚动位置；
4. 现有测试只验证数据投影和结果评审，不验证浏览器可视区域内的轴元素位置。

### 明确排除的方向

- 不是 `pes_profile.json` 缺少扫描坐标；
- 不是能量 series 为空；在有可绘制点时轴 markup 会被生成；
- 不是轴被曲线绘制顺序覆盖。轴组在曲线绘制之后追加，DOM 层级上位于后面；
- 不是用户截图中的任务日志或错误提示要求执行某个操作。截图仅作为视觉证据使用。

## 6. 影响评估

### 用户影响

- 无法同时看到能量曲线和完整坐标系；
- 无法可靠读取横坐标对应的扫描距离/进程；
- 选择 TS/INT 候选时，点的位置与扫描坐标之间缺少可见映射；
- 用户可能误以为坐标数据不存在，或依赖右侧详情面板手工核对每个点；
- 缩放和重绘后视图状态不稳定，降低能量图作为审查工具的可信度。

### 科学/业务影响

该问题不会直接修改计算结果，但会削弱结果解释和人工复核能力。对 PESsearch 而言，横轴是判断扫描进程、候选点位置以及目标/实际坐标关系的必要语义；横轴不可持续显示时，图表不能作为完整的审查证据交付。

## 7. 修复方向（本报告不实施代码修改）

1. 将图表拆成“固定轴层 + 可缩放/平移绘图区”，至少把左侧 Y 轴和底部 X 轴从滚动内容中分离；
2. 如果继续使用 SVG，保证轴层始终覆盖在图表视口内，曲线层只在 plot rectangle 内裁剪；
3. 重新设计图表高度计算，避免 `height:100%`、`min-height` 和父级 `minmax(0,1fr)` 叠加后让轴区域溢出；
4. 不要用全量 `innerHTML` 替换破坏视图状态；必要时保存并恢复滚动位置，或改为更新既有 plot/axis 节点；
5. 检查优化图和旧机制能量图的独立渲染路径，避免只修复 PESsearch 路径后出现同类问题。

## 8. 验收标准

- 在用户截图对应的桌面尺寸和中央面板高度下，横轴线、横轴刻度、横轴标题、纵轴线和纵轴刻度同时可见；
- 图表出现滚动或缩放时，坐标轴仍固定在图表可视区域内，不被滚动条遮挡；
- 选择帧、切换 series、缩放、框选、平移、窗口 resize 和实时刷新后，坐标轴仍可见，且 domain/刻度值正确更新；
- 图例与横轴区域不重叠，结构查看器和工作台其他面板不覆盖坐标轴；
- 至少增加一组前端视觉/DOM 回归检查，覆盖正常高度、短高度、窄宽度和重绘后的状态；
- 现有能量图数据投影测试继续通过。

## 10. 最终结论

当前 ACP 能量图的核心缺陷是：**坐标轴被实现为可滚动 SVG 内容的一部分，而不是始终固定在可视图表区域中的坐标层**。截图已经显示该缺陷的用户可见结果——纵轴部分存在、横轴信息被底部区域裁切，且图表出现双向滚动条。修复重点应放在图表容器和轴层的布局契约，而不是修改能量数据或简单补画一条横线。
