# 三端四模块架构：前端显示 · 中端传输控制 · 后端计算与绘图

> 历史方案：2026-10-16 后续讨论已确认 ACV 归前端，3Dmol 由 ACV 封装，科学大数据处理与规范化输入输出归 CCCP。本文后端 ACV/独立 render worker 目标由[新版三层架构](../../../reference/next-change/ACP_Three_Tier_Architecture_20261016.md)替代；以下原稿仅留作设计演进记录，不能作为当前迁移指令。

日期：2026-10-15。状态：设计提案（承接前三份设计稿 + 两轮讨论的演进版）。**未修改运行代码、未重跑探针、未重启服务。**
与既有文档关系：本文在《三模块边界 ADR》《子层设计》《架构评审与执行方案》基础上演进——平台按**三端**组织，绘图收敛为后端**独立模块 ACV**，并新增**绘图复用设计**（§2）。

本轮三个关键决定：
1. 平台拆分为**三端**：前端显示端 · 中端传输与控制端 · 后端计算与绘图端；
2. **绘图能力 = 后端独立模块 ACV**，并设计"最大化复用"；
3. **CCCP 本轮零改动**——科学结果的数据处理与统一格式封装确认为 CCCP 职责（所有权收敛列后置阶段）。

---

## 0. 决策摘要

- **三端四模块**：前端 = ACP；中端 = ACR；后端 = CCCP（计算）+ ACV（绘图），两个独立模块同属后端端。
- **绘图复用四条主线**：① 单一绘图核心（视图引擎 + 注册表）；② 单一数据入口（CCCP 统一格式）；③ 一次装配多种输出（交互载荷 / 静态图 / 文档 / 导出）；④ 前后端各一个通用渲染核心（契约共享）。
- **边界三不许**：ACR 无绘图、无科学加工；CCCP 无绘图、无平台状态；ACV 不解析、不写状态、不传输。
- 逻辑三端**现在成立**（同仓、模块独立、单向依赖、独立测试）；物理进程拆分按既有触发条件后置。

## 1. 三端模型

```
┌───────────────────────── 前端显示端 ──────────────────────────┐
│ ACP：浏览器渲染与交互 · 通用图表渲染器 · 通用 3D 渲染核心            │
└───────────────────────────┬──────────────────────────────────┘
                    产品 API / SSE（单一入口，版本化）
┌───────────────────────────▼──────────────────────────────────┐
│ 中端传输与控制端  ACR                                            │
│ 网关 · 控制（状态/CAS/调度/命令）· 传输（文件/远端缓存）· 记录          │
│ （无绘图、无科学加工）                                            │
└──────────┬───────────────────────────────────┬───────────────┘
      展示请求 →                           执行信封 →
┌──────────▼───────────────┐      ┌───────────▼───────────────┐
│ 后端 · 绘图模块 ACV         │◄─只读─│ 后端 · 计算模块 CCCP         │
│ 视图引擎 + 输出器（独立模块）  │ 统一格式│ 科学处理 + 统一格式（零改动） │
└──────────────────────────┘      └───────────────────────────┘
```

| 端 | 模块 | 角色 | 唯一问题 | 数据形态 |
|---|---|---|---|---|
| 前端显示端 | ACP | 渲染与交互 | 用户如何使用系统 | 像素与交互 |
| 中端传输与控制端 | ACR | 网关 / 控制 / 传输 / 记录 | 系统如何可靠地安排、记录、搬运 | 平台记录与搬运 |
| 后端·计算 | CCCP | 科学处理与统一格式 | 科学如何被计算与验证 | 科学真值 |
| 后端·绘图 | ACV | 绘图 / 可视化 | 数据画成什么样 | 呈现形态 |

关键关系：前端只连中端；中端调用后端两个模块；**ACV 只读消费 CCCP 统一格式**（后端内部唯一允许的依赖边）。

## 2. 绘图复用设计（本轮核心）

### 2.1 前提：单一数据入口

绘图的最大复用来自数据形态统一：**所有绘图输入 = CCCP 统一格式产物 + ACR 授权的工件引用**。格式统一后，视图可以"声明式描述"，引擎才能通用化；这是与"科学结果处理与封装归 CCCP"原则的直接衔接。

### 2.2 复用图谱（现状 → 目标）

| 复用维度 | 现状 | 目标 |
|---|---|---|
| 跨视图 | 12+ 个专用展示构建器 + v1 路由内联（能量/采样/IRC/PES/振动/结构/热化学/机制/报告各一套） | 一个引擎 + 每类视图一个注册 spec |
| 跨输出 | 交互载荷与报告/图片两套路径（viewer 载荷独立 JSON；nmr 报告独立 matplotlib） | 同一 ViewModel 多输出器，交互与静态同源 |
| 跨端 | 服务端与前端各自实现绘制逻辑，形态不共享契约 | 服务端出视图模型（ACV）、前端通用渲染（ACP），契约唯一 |
| 跨消费者 | 基本只服务工作台 | 工作台 / 报告 / 导出 / 未来 API 消费者共用同一视图模型 |

### 2.3 单一绘图核心：视图引擎 + 注册表

- **统一视图模型（保持最小，仅四类）**：`series`（曲线/散点）、`frames`（3D 帧与注解）、`tables`（表格）、`annotations`（标注组合）。
- **view spec 声明**：view_type、数据契约（统一格式中的哪些字段）、到视图模型的映射、默认轴/单位/主题、允许的输出器集合、版本号。
- **引擎职责**：装配、展示级下采样、注解组合、版本与缓存键生成；**工作流无关**。
- **扩展方式**：新增视图 = 注册一个新 spec（含版本），零引擎改动；禁止新增专用绘制路径。

### 2.4 一次装配，多种输出（ViewModel → Emitters）

| 输出器 | 载体 | 用途 |
|---|---|---|
| 交互 JSON | ACR 端点 → ACP 通用渲染器 | 工作台交互 |
| 静态图（PNG/SVG） | matplotlib（**唯一驻地**） | 报告 / 摘要 / 导出 |
| 文档表格（XLSX/CSV/JSON） | 报告文件 | 数据下载与复核 |
| 导出包 | 归档 / 二次分析 | 下载 / 复现 |

原则：**同一 ViewModel，多个输出器**；交互与静态禁止两套实现；输出器只消费 ViewModel，不感知工作流。

### 2.5 前端通用渲染核心（ACP 侧复用）

- **图表核心**：一个系列渲染器覆盖能量/采样/IRC/PES/谱图（spec 提供轴、单位、主题、交互开关）。
- **3D 核心**：一个查看核心覆盖结构/轨迹/振动（frames 模型 + 注解）。
- 面板职责 = 请求视图 + 传参 + 响应事件；迁移完成的面板不再自带绘制代码（逐面板下架旧实现）。

### 2.6 扩展方式与护栏

- **自动化检查**：绘图实现唯一性（`src/` 中 ACR/CCCP 出现绘图调用 = FAIL；前端绕过通用渲染核心的私有绘制 = 审计项）；spec 注册覆盖率（每个 view_type 必须有 spec）；迁移期**载荷字节兼容**（先复刻、后收敛）。
- **复用度量**：交互与静态同源率；新增视图的引擎改动行数 = 0（样板验证）；同一 spec 服务的消费者数。

### 2.7 反过度设计边界

- 核心视图模型保持最小四类；专用形态（复杂 3D 载荷、谱图峰表）放 spec 或专用输出器，不进核心。
- 允许"专用构建器"，但必须注册为 spec、经引擎与输出器，不允许旁路。
- 不为复用牺牲科学正确性：任何科学计算仍归 CCCP；ACV 只负责形态。

## 3. 各端模块清单

### 3.1 前端显示端 = ACP

沿用编号 A0–A5（见层级地图）。本轮唯一变化：**A1.3 ui/viewers 内部按"通用渲染核心"重构**（图表核心 + 3D 核心），A3 数据协调层不变。

### 3.2 中端传输与控制端 = ACR

沿用编号 R1–R7。**全体绘图职责已移出**：入口（R1）、命令（R2.1/2.2）、规划（R2.3）、执行（R2.4/2.5）、发布登记（R2.6）、传输（R2.7）、操作性查询（R2.8）、同步（R2.9）、组织（R2.10）、流程（R2.11）；领域 R3、适配 R4、契约 R5、装配 R6、平台兼容 R7。ACR 内**不存在**任何绘图/视图构建实现。

### 3.3 后端·计算模块 = CCCP

C0–C5 不变。职责确认：**科学结果处理（解析、派生、判定）与统一格式封装**。本轮零改动；统一格式的"权威定义"收敛到 CCCP 列入后置阶段（现状以 `result_manifest v2` + products 为事实标准）。

### 3.4 后端·绘图模块 = ACV

| 编号 | 子层 | 职责 |
|---|---|---|
| V0 | 视图契约与注册表 | 统一视图模型（series/frames/tables/annotations）、view spec 登记、版本与缓存键 |
| V1 | 视图引擎 | 统一格式 → 视图模型：装配、展示级下采样、注解组合；工作流无关 |
| V2 | 输出器与报告 | 交互 JSON / 静态图（matplotlib 唯一驻地）/ 文档表格 / 导出包；报告编排 |
| V3 | 数据访问与缓存 | 统一格式读取适配（结果根由 ACR 提供）、展示缓存、旧数据展示兼容 |

**ACV 三不许**：不解析原始程序输出、不派生科学量（→ CCCP）；不写平台状态、不落科学产物（→ ACR）；不碰传输（→ ACR）。

### 3.5 模块独立性五条标准

1. 各自公开契约，跨端只经契约调用；
2. 依赖单向：前端 → 中端 → 后端；`ACV → CCCP`（只读）为唯一后端内部边；
3. 可独立测试（契约替身，不依赖真实对端）；
4. 变更影响面限定端内（版本化契约变更才跨端）；
5. 资源与生命周期独立：前端空闲降频；中端**快路径**（不含慢活）；后端慢活队列。

## 4. 跨端契约与禁令

| 通道 | 方向 | 载荷 | 约束 |
|---|---|---|---|
| 产品 API | ACP ↔ ACR | 命令 / 查询 / 事件 / 展示载荷获取 | 单一入口、版本化、幂等键 |
| 执行信封 | ACR → CCCP | 冻结计划、输入工件、资源预算 | 唯一执行者；平台身份不进科学身份 |
| 科学结果 | CCCP → ACR | 统一格式工件与回执 | ACR 只登记与传输，不做内容加工 |
| 展示请求 | ACR → ACV | 工件引用 + view_type + 参数 | 根由 ACR 提供；ACV 不含远程拉取 |
| 展示载荷 | ACV → ACR | 版本化 ViewModel / 输出产物 | 可缓存、多人复用、字节兼容迁移 |
| 只读消费 | ACV → CCCP | 统一格式读取 + 按需解析服务调用 | 单向；不执行计算 |

**禁令**：前端不直连后端两端；ACR 内不出现绘图；CCCP 不导入 ACP/ACR/ACV；ACV 不导入 ACR 内部、不写平台状态；解析与科学派生不得在 ACV 复制实现。

## 5. 现有代码去向（承接前轮清点）

- **绘图族 → ACV**：12 个展示构建器（energy_graph、sampling_graph、irc_projection、pes_profile、pes_scan_live、structure_viewer、vibration_projection、frequencies-payload、frame_candidate_geometry/annotations、optimization、thermochemistry）收敛为"引擎 + spec"；`nmr/report.py` 与机制报告 → V2。
- **混合模块拆除清单**（先切解析/派生与绘制的分离点）：`pes_scan_live`、`vibration_projection`、`structure_viewer`（geometry fallback）、`irc_projection`（raw trj fallback）、`frame_candidate_geometry`（材料化 vs 序列化）、`frequencies`（产品写入 vs payload）、`v1_routes` 内联发现函数。解析族**暂留原位**（标"CCCP 目标，暂缓"），经窄接口调用。
- **CCCP 零改动**：不迁入、不迁出、不新建第二实现。

## 6. 部署映射与阶段

| 三端 | 当前部署 | 触发后 |
|---|---|---|
| 前端 | 浏览器静态资源 | — |
| 中端 | `acp run serve`（API + 控制同进程） | controller 独立进程（沿用既有触发表） |
| 后端·计算 | 本地子进程 / 远端 worker | 维持 |
| 后端·绘图 | 同进程模块（ACV） | 独立服务/进程（慢活队列的天然宿主） |

与既有执行计划（S0–S2）的关系：不冲突——S0/S1 属中端与前端；"视图 spec 化"收敛接在 S2 之后，作为展示层的统一路线。

## 7. 验收与护栏

- 绘图实现唯一性：ACR/CCCP 内绘图调用 = 0；
- spec 覆盖率 100%（登记清单审计）；
- 至少一类视图达成"交互与静态同源"样板；
- 新增视图"零引擎改动"样板验证；
- 载荷迁移期字节兼容（前端零改动）；
- 不关闭任何既有护栏与测试；ACV 不复制解析/科学算法。
