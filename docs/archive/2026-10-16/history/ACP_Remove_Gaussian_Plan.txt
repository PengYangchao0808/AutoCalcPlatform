

ACP 移除 Gaussian 支持 · 实施计划

目标：从 cccp 与 acp 全栈移除 Gaussian 16 计算路径，简化基组/方法支持与工作流配置；NMR 切换到 ORCA 端到端；保留只读 GJF/Gaussian-log 解析能力；前端与配置移除 engine 选项统一走 ORCA。

0 · 关键调研发现

  ORCA NMR 已在代码层可用（文档滞后） — 实际检查：ORCAInterface.nmr_shielding()（src/cccp/qc/interfaces/orca.py:471-537）已完整实现，写 ! ... NMR 输入、跑 ORCA、解析能量；parse_orca_nmr_log()（src/acp/nmr/parser.py:150-218）解析 "NMR SHIELDING TENSOR" 段。真正的阻断点只有三处：
  
    
src/acp/cli.py:756-760 — 硬编码拒绝 --backend orca 跑 NMR（错误信息"not implemented yet"已过时）
    
src/acp/backends/capabilities.py:67 — orca.nmr=STUBBED
    
默认值链路 workflows/nmr.py:33,35 / config.py:181 / defaults.yaml:72 默认 gaussian
  
  ⇒ "先实现 ORCA NMR 端到端"实质为「解锁 + 改默认 + 改能力声明 + 跑通验证」，无需新写计算/解析代码。

  Gaussian 实际生效面比想象窄：shipped 默认配置 theory.optimization/frequency/single_point.engine='orca'，仅 NMR 默认 gaussian；opt/freq 走 gaussian 只在用户显式指定或协议回退时发生。删除影响主要落在：默认回退、validation 强制回退到 gaussian、catalog 前端默认、NMR 工作流、GJF/log 解析、scheduler/remote 同步脚本。

1 · 决策摘要（来自确认）

  
 | 议题 | 决策

  
 | NMR 后端 | 切换到 ORCA 端到端（解锁现有实现即可）

  
 | GJF / 历史 .log | 保留只读解析（删 write_gjf，保留 read_gjf/parse_gjf_text/_parse_gaussian_log 用于读入历史文件）

  
 | 改动范围 | 全栈：cccp + acp + 前端 + 脚本 + 测试

  
 | 配置兼容 | 前端与配置移除 engine 选项，全部使用 ORCA（硬切换，不再暴露/接受 backend 选择）

2 · 本地与远程节点同步注意事项

  远程节点是关键影响面：删除 scripts/run_g16_worker.sh 后，远程计算节点上已同步的副本会变成悬空文件，且远端无需再探测 g16。
  
    
src/acp/scheduler/remote/sync.py:11,111-114 删除 run_g16_worker.sh 同步条目（Phase D 已含）；后续任务不再向远端推送该脚本
    
手动清理远端既有副本：rm $REMOTE_WORKDIR/scripts/run_g16_worker.sh；否则旧脚本残留可能被误用
    
远端 g16 可执行若仍存在不影响功能，但建议在远端环境变量 / 模块加载里停用 Gaussian 环境（module unload gaussian 或清理 g16root/GAUSS_EXEDIR）
    
requires_binaries 校验逻辑删除 "gaussian" 后，远端二进制探测清单自动不再要求 g16，无需额外改远端探测代码
    
执行顺序：先在本地仓库完成 Phase A–D 并重启服务，确认新任务不再引用 Gaussian；再去远端执行 rm 与停用环境，避免正在运行的旧任务因脚本缺失中途崩掉
    
核对：完成后再抽一个 conformer + NMR 任务的远端执行做烟雾测试，确认远端清单更新生效

风险矩阵

  
 | 风险 | 等级 | 缓解

  
 | NMR 在 ORCA 实跑未验证（真实轨道/溶剂/收敛） | 高 | Phase A 用一个小分子（如甲烷/水）对 ORCA NMR 实跑端到端，人工核对屏蔽张量，再进 Phase B

  
 | 历史 / 外部配置仍传 engine:"gaussian" | 中 | config 校验对残留 gaussian engine 记 WARNING 后置 orca（平滑），不硬崩

  
 | LogParser 双引擎解析被破坏（影响 .log 读入） | 中 | 保留双引擎 parser，仅去掉 .log 默认偏向 gaussian 的自动路由

  
 | ProtocolSpec 默认值翻转影响多协议 | 低 | defaults 改 None→解析为 orca，避免硬编码 engine 名

  
 | 文档 / AGENTS.md 残留 Gaussian 描述 | 低 | Phase H 集中更新

  
 | 远端残留 run_g16_worker.sh 被误用 | 中 | 本地仓库改完并重启服务后再去远端 rm 并停用 Gaussian 环境（见 §2）

执行顺序与门禁

  
Phase A（打通 ORCA NMR）→ pytest 绿 + 1 个真实 ORCA NMR 跑通 [门禁 A]
  
Phase B + C（删后端、改默认）→ pytest tests/test_engine_routing.py tests/test_config.py tests/test_acp_workflows_conformer.py -v 绿 [门禁 BC]
  
Phase D + E + F（catalog/前端/只读解析）→ API 烟雾：GET /api/backends 无 gaussian；前端提交任务成功 [门禁 DEF]
  
Phase G（全量测试）→ pytest tests/ -v 全绿 + ruff check/ruff format --check/mypy 通过 [门禁 G]
  
Phase H 文档；sudo systemctl restart acp 重启服务（用户执行），前端核对
  
远端清理（手动）：删 run_g16_worker.sh、停用 Gaussian 环境、远端烟雾测试

回滚策略

每阶段一个 git commit（Phase A/B/C/D/E/F/G 各一笔），任一门禁失败可 git revert 该笔而不影响先前已通过阶段。Phase A 一旦通过，NMR 即不再依赖 Gaussian，删除 Phase B 即不会让 NMR 失能——这是回滚安全的关键顺序。

关于服务密码

本计划不写入任何密码或敏感凭据。sudo systemctl restart acp 由用户本人执行，避免密码进入版本库或会话历史。

—— 计划基于代码现状调研；执行前需在真实 ORCA 环境验证 NMR 端到端（Phase A 门禁）。生成于 2026-07-16。
