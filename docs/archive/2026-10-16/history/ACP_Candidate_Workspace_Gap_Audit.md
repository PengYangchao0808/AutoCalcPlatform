# 新建任务候选工作区：实现差距与后续完善方案

日期：2026-09-23。依据：最新用户截图、当前工作区代码、原方案及其第14节实施记录。

本轮为审查与方案编写，未修改业务实现。检查方式为截图审阅、代码调用链核对及相关测试；未在真实运行服务中逐项操作，因此将截图事实、可确定代码缺陷和待运行验证项分别表述。

## 1. 结论

当前实现完成了入口合并、四来源导航、共享来源分类接口及部分状态逻辑，但尚未达到原方案的可用性和视觉目标。主要问题是组件接线与状态闭环不完整，而不是缺少更多装饰。

右下角空白可以对应到两个确定原因：详情容器仍被 CSS 隐藏；输入清单沿用了默认折叠抽屉。候选选择则存在紧凑渲染器与 multi 模式不匹配。应先打通真实数据交互，再重排布局，最后做有数据的浏览器验收。

## 3. 优先修复：交互和数据一致性

以下作为发布前必须修复项；优先级不表示所有问题都已在运行服务中复现。

### A1. 紧凑列表缺少逐项选择，载入按钮无有效回调

位置：`frontend/js/structure_source_picker.js::_renderEditorRow/_handleLoad`；HTML 中 `loadCandidateSources/loadStructureSources`。

两个工作区 picker 都配置 mode=multi、density=editor。editor 渲染器不生成 `.sp-row-cb`，但仍生成载入按钮。按钮进入 `_handleLoad` 后仅调用 `onLoadItem`，这两个挂载点均未提供该回调。与截图中有“载入”和“全选本页”、却没有逐行勾选一致。

修复：editor renderer 明确支持 multi；显示逐项复选框，去掉该模式的遗留载入按钮，以勾选为唯一加入方式。垃圾箱模式勾选仅服务于管理，不能受 active 输入可用性条件错误禁用。集合/轨迹提供“打开并选帧”，不把集合当作普通单结构加入。

验收：点击名字只预览；勾选、取消、当前页全选和取消均准确更新输入；每种来源和垃圾箱模式分别验证。

### A2. 右侧详情被 CSS 持续隐藏，输入清单默认折叠

位置：`frontend/css/task_input_workspace.css` 的 `.tiw-right > .tiw-details-host {display:none}`；`candidate_details.js::_render`；HTML 的 loaded-structures-drawer 样式与结构。

组件有 entry 时仅执行 `_host.style.display=""`，恢复的仍是 CSS 的 display:none，因此内容虽生成却不可见。输入抽屉则要求 `.open` 才显示，且垃圾箱入口也放在抽屉头中。

修复：统一用 hidden 属性或单一状态类管理可见性，移除互相冲突的 display 规则。DOM 固定为预览→详情摘要/管理→本次输入；输入即使为0项也显示短空态。垃圾箱入口移到左侧来源列表工具栏，不依赖已选择输入。

验收：选中任意候选后真实 computed style 可见，右侧名称与几何一致；0项、1项、多项输入清单均可见；未添加输入也能进入垃圾箱。

### A3. 双来源选择可能静默移除其他页输入

位置：HTML `_syncPickerSelection`、两个 picker 的 onChanged；picker `setSelection/getSelection`；workspace `reconcileSelection`。

同步只传所有 UID；setSelection 清空旧快照，并仅从当前 picker 的项目解析 UID。另一来源/其他页的 UID 可能没有快照，getSelection 不返回它们；reconcileSelection 又将返回集合视作完整选择，从而删除未返回的库输入。

修复：以 wizard 输入为唯一权威，picker 发出新增/取消 UID 的增量事件；或者传全量稳定快照并严格定义作用域。取消当前页一项不得重建全部库选择。刷新、切来源、切项目范围和翻页都不得隐式删除输入。

验收：候选A→任务结果B→候选C→取消C，输入仍为A+B；搜索到其他页后继续勾选也保持此前输入。

### A4. 垃圾箱行菜单只画出按钮，没有操作绑定

位置：HTML `_wizardTrashRowMenu`。

函数构造并显示“恢复候选/彻底移除”，设置焦点后即结束，没有点击处理、键盘处理或 `_activeRowMenu` 清理登记。正常菜单的实现没有被复用。

修复：共用一个有事件、键盘和销毁机制的菜单组件，由 active/trash 状态决定命令。Esc/点击外部关闭，关闭后归还焦点，避免重复菜单残留。

验收：真实点击与键盘都能触发恢复/确认删除；取消不发写请求。

### A5. 清空垃圾箱参数不符合 API，项目和来源范围也需统一

位置：HTML `_wizardEmptyProjectTrash/_enterWizardTrashView/_wizardTrashPurgeSelected`；API list_structure_sources。

- 前端使用 limit=200，接口限制最多100，按契约会返回422。
- 循环增加本地 page，却没有传 cursor，降低limit后仍会重复抓第一页。
- 进入垃圾箱仅切 usageStatus，未清除 sourceGroup，因此只显示当前来源类别，非计划中的统一垃圾箱。
- purge 使用目标项目而非条目真实来源项目；显式禁止 uncategorized，导致默认项目无法按正常项目管理。
- 垃圾箱标题计数取“已选数量”，不是垃圾箱总数。

修复：使用limit≤100和服务端next cursor，UID去重，确认时冻结集合。区分目标项目与来源范围；默认项目按合法项目身份处理。统一垃圾箱查询，退出恢复原来源条件。总数、筛选结果数和已选数分别显示。跨项目条目按真实项目分组提交，全部项目视图无全量清空。

验收：0/1/101/205项、默认项目、跨项目、不同来源的垃圾箱均完整且无重复；确认后新增的条目不被误清理。

### A6. 撤销保存了列表快照，而非被移除的完整任务输入

位置：HTML `_wizardMoveToTrash/_wizardUndoTrash`。

priorEntry 保存 target.snapshot，未保存 wizardStructures 中的实际条目。恢复时把列表快照直接 push 为输入，可能缺失 xyz、input_id、geometry_state，以及用户修改过的角色/电荷等。多次操作还向同一个 undo targets 累加，没有独立操作身份和版本一致性检查。

修复：操作前按UID捕获完整输入副本，记录 operationId、顺序、版本、服务端成功 revision。撤销只针对该操作成功项；先恢复服务端状态，确认版本后恢复完整输入。版本变化时只恢复库条目并要求重新选取。不叠加多个同ID通知，失败项保留重试信息。

验收：修改过名称/电荷/角色的输入移入后撤销能完整恢复；连续两次移入的撤销目标准确；其他窗口修改导致409时不覆盖。

### A7. 元数据保存会制造自身 revision 冲突

位置：`candidate_details.js::_save/_markDirty`。

重命名和标签分两次 PATCH，但第一次成功后未使用返回 revision；第二次仍提交旧revision。仅改名称也会被评估原因的无条件必填校验阻止；统一 dirty 收集还可能在只改名称时附带创建评估。

修复：名称和标签合成单次 metadata PATCH；评估作为独立变更，仅评估发生变化时校验原因并提交。每个成功响应更新本地版本；部分成功需明确保留未完成字段；保存后刷新列表与详情。

验收：仅重命名、仅标签、两者一起、仅评估、外部409分别正确；不产生无意的评估记录。

### A8. 详情异步请求和未保存切换不一致

位置：`candidate_details.js::refresh/setEntry`；HTML onPreviewItem。

refresh 创建 AbortController 却未将 signal 传入请求，响应也没有核对 UID/token。A慢响应可以写入当前B详情。onPreviewItem 先启动几何预览再调用有未保存确认的setEntry；用户拒绝切换时，几何已经转向B而详情仍为A。

修复：切换许可统一前置，通过后原子更新列表焦点、几何、详情；所有请求校验会话+UID+版本token，接入真实取消信号。保存期间切换也要限定响应归属。

验收：A慢/B快、保存中切换、拒绝放弃编辑三种情景下，右侧身份和结构始终一致。

## 4. 后续视觉与功能完善

### B1. 将右侧重新组成三段

预览约240–280px；详情摘要展示名称、来源、编号、四态评估与标签；管理表单点击“编辑”展开；本次输入固定可见且列表局部滚动。右侧增加移入/恢复动作，左侧增加当前可见勾选项的批量移入入口。

不要直接把目前整个评估表单全部展开填入空白区；那会由“空”变成拥挤。正常阅读优先，编辑按需展开。详情名称允许换行，version_id 不得标成“帧编号”。

### B2. 收紧顶部和左侧信息密度

截图中的明确偏差：关闭二字竖排、标题贴边、仍有“2.选择结构来源”、目标项目说明重复、空选择时两枚禁用操作按钮独占一行、列表存在水平滚动。

修复：关闭保持×图标并使用aria-label；标题加统一内边距；项目说明去重；来源区只保留标签导航；无勾选隐藏批量操作条。列表改两行式，不再把名称/来源/时间/角色/按钮全塞一行。左侧容器禁止无意横向溢出，而非隐藏被截断操作。

右栏宽度约束为360–480px（合适视口），窄屏堆叠；现有3:2网格并未限制右侧最大宽度，也未实现拖动分隔线。拖动可排在核心修复之后，但需明确是未完成项。

### B3. 草稿不能只保留选中结构

closeJobModalGuarded 仅保存结构、索引、来源页、步骤；openModal仍清空文本、上传文件引用、备注、任务名并重置若干配置。按钮“关闭并保留草稿”因此表意过宽。

修复：定义完整内存草稿，包括项目、输入、手工文本、上传对象引用、当前步骤、工作流配置和视图状态。新建初始化与恢复分开；编辑重算继续使用原锁定/预览提交契约。明确刷新不保证恢复上传文件。

### B4. 统一状态模块与操作反馈

`ACPTaskInputWorkspace.mount/render` 目前仍是空实现。应把来源/垃圾箱/输入/预览的生命周期与事件管理真正迁入模块，HTML只接线，避免增加更多全局状态。

补齐失败输入重试、外部版本变化处理、部分失败列表、右侧管理动作、中英文覆盖和焦点返回。打开来源任务应进入工作台任务详情；当前行菜单 window.open 到API JSON，不符合用户导航预期。
