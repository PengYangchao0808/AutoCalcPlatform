# acp-runtime-contract-remediation - Work Plan

## TL;DR (For humans)

**Who this is for and what changes for them:** People who submit and manage jobs in the ACP Workbench (and the science reviewers who trust its reports): cancellations stop leaving ghost artifacts, the task list stops showing two different statuses for the same job, recalculation no longer dies on a multi-frame conformer file, remote results become readable/downloadable (including files not yet cached), and the scan wizard finally lets you pick the atoms to scan with real validation.

**What you'll get:** A revised execution of the nine runtime-contract fixes plus a baseline/contract-freeze delivery (task 1) and the task 2-14 remediation set, organized as delivery units R0-R10 instead of fixed waves. Every previously reviewed requirement is kept; the revision adds cross-attempt isolation, frozen report/checkpoint contracts, deterministic resume credentials, bounded eventual consistency for the task projection, on-demand remote downloads, lifecycle rollback, real-wizard scan validation, and delayed-response cache freshness.

**Why this approach:** The first review round (Momus + independent Oracle) approved the direction but the user's follow-up review (`.omo/plans/acp-runtime-contract-remediation-improvement-plan.md`) found implementation-closure gaps in concurrency isolation, resume credentials, and acceptance loops; this revision folds every mandated requirement and the deterministic `/tmp` reproductions, and drops the fixed wave-count decomposition in favor of R-units driven by user outcomes and file conflicts.

**What it will NOT do:** No new workflows, CLI flags, DB tables/columns, or migrated state changes; no angle/dihedral scan UI in the first phase (distance-only); no rewriting of execution-integrity invariants; no real QC binary runs described as scientific verification; no commits of `.omo/` artifacts or the user's existing uncommitted changes.

**Effort:** Large
**Risk:** High for the scheduler state machine and TS Mode resume chains (tasks 2, 4, 5, 7); Medium for the remaining units - do not summarize the whole plan as Medium.

**Decisions to sanity-check:** (a) tasks stays a repairable projection with bounded eventual consistency (jobs authoritative), with a short-transaction/versioned sync; (b) TS Mode report keeps a FLAT `resolved_level` plus a flat `source_level` sibling; (c) TS Mode checkpoint v2 freezes explicit stage credentials and a recompute decision table; (d) remote reads fetch missing files on demand through the manager cache singleton (never into work_dir); (e) scan ships distance-only with shared v1/v2 validation at the submission boundary; (f) task 7 stops background work before releasing ownership.
