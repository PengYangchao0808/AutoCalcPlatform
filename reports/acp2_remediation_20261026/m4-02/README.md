## Legs

1. `model/` — the M4-01 full product chain in its `--model model-gateway`
   branch: the DSH product planner calls the Controller model gateway
   (M3-03 reservation + settlement + trusted receipt) and the chain runs
   round 0 and the evidence-feedback round 1.
2. `injection*` — an artifact carrying approval/budget override text is
   handed to the model as data; the platform validator and the platform
   records decide, and the orchestrator re-reads them.
3. `science` — real Local submissions (`singlepoint`, `optimize`,
   `frequency`, `xtb_optimize`) on an isolated run root with native
   outputs, manifests, release/attempt/receipt facts and digests.
4. `taskref-*` — CLI, MCP and the Workbench client modules read the same
   TaskRef (Workbench runs the real frontend modules in Node, no browser).
5. `browser/` — the two registered C rows executed for real:
   `same-task-browser-live` (bundled Chromium + system Edge, one TaskRef,
   read-only identity refused) and `approval-budget-live` (two acting
   identities approve/reject/revoke, a read-only identity refused, an
   over-budget submit refused).  Screenshots, console and network records
   live beside each row's `acp2.acceptance.v1` receipt.
