# ACP remote compute-node runtime dependencies
# ============================================
# Installed by `NodeManager.bootstrap_node()` (POST /api/v1/nodes/{name}/bootstrap)
# and auto-synced to each node's ``remote_code_dir`` by :class:`CodeSyncer`.
#
# This is the execution-side subset of the project dependencies declared in
# ``pyproject.toml`` — the API/server/scheduler/dev tooling
# (fastapi, uvicorn, paramiko, pytest, ruff, ...) is NOT needed on compute
# nodes and is deliberately omitted to keep nodes slim.
#
# The ACP codebase requires Python 3.10+ (``typing.TypeAlias``, PEP 604
# unions).  Bootstrap and job submission resolve the interpreter on the node
# via `detect_node_python()` — a node whose system interpreter is 3.9 is
# automatically re-routed to a newer interpreter (e.g. anaconda/miniconda)
# or rejected with configuration guidance.  Set ``cluster.nodes[].python_executable``
# to pin a specific interpreter per node.
#
# Add any new runtime import used by ``acp run <workflow>`` here as well as
# in ``pyproject.toml`` so bootstrapped nodes stay in sync.
#
# Sync policy (todo 32): every line below must appear VERBATIM in
# ``pyproject.toml`` (core ``[project].dependencies`` or the ``nmr`` extra)
# — drift-locked by ``tests/test_packaging_assets.py``.  scipy / matplotlib
# / openpyxl are REQUIRED on nodes: for a remote job the whole workflow runs
# on the node (DP4/DP5 + regression need scipy, report plots need
# matplotlib, the XLSX report writer needs openpyxl — without it the XLSX
# artifact would be silently skipped in the node log).
#
# Deliberately NOT shipped to nodes:
#   qml        — only builds against numpy<2 (platform pins numpy>=2.1.0);
#                FCHL/DP5 degrades to the documented unweighted-KDE fallback
#                (acp.nmr.error_model), with explicit errors when a kernel
#                is required but absent
#   openbabel  — FCHL ``frag_reps.gz`` fragmentation path not wired yet
#                (stays in the ``nmr`` extra)
# nmrglue IS shipped: remote nmr jobs may submit a Bruker tree
# (``--bruker inputs/bruker`` from ``script_gen.build_remote_nmr_cmd_tail``)
# which stage 0a processes on the node.
